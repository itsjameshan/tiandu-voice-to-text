# 使用 AI 编程工具的注意事项

本课程允许、也鼓励大家借助 AI 编程工具（如 Claude、豆包、通义灵码等）读代码、写代码、查错。但要遵守下面的规矩。

## 一、绝对不能做的（红线）

1. **不能把任何录音、真实投诉材料、真实个人信息粘贴或上传给 AI 工具。** 包括本班同学录的剧本录音——它们只在机房和老师电脑上处理（见同意书）。
2. **不能用 AI 生成"人说话"的音频**（语音合成、声音克隆），也不能用它把剧本"念"成录音。
3. **不能让 AI 把工具改成联网处理录音**（调用云端识别接口、公共大模型）。
4. 不能把同学的真实姓名、学号、手机号写进代码、报告或提交说明。

## 二、可以放心给 AI 看的

- 本组负责的代码文件（如 `pipeline/groups/g1_denoise.py`）和对应的基线代码；
- 报错信息（黑色窗口里的红字）——先检查里面有没有个人信息（例如路径里的中文用户名，可以删掉再贴）；
- 测评输出的数字表格（字错率、准确率等）；
- 本仓库的文档（README、任务书、`docs/build_spec.md`、`GLOSSARY.md`）。

> 用 Claude Code 打开本仓库时，它会自动读取根目录的 `CLAUDE.md`，里面写了红线和项目约定。

## 三、好的用法

- **让它解释代码**："请逐行解释 `pipeline/step2_vad.py` 里的 `detect_speech` 在做什么，我是初学者。"
- **让它出改进思路，再自己选**："第 1 组要改进降噪，基线是什么都不做。请列出 3 种由易到难的方法，各自的优缺点，以及怎么用字错率验证。"
- **让它先写测试**："为我写的函数写一个 pytest 测试，输入一段 3 秒的正弦波，检查输出长度不变。"
- **查错时给全信息**：说明你运行了什么命令、期望什么、实际看到什么、完整的报错。

## 四、要求

1. **AI 写的代码你必须读懂、能讲清楚。** 答辩时老师会随机指着代码问"这一行在做什么、为什么这样做"。讲不清的部分不得分。
2. **改完一定要跑测评**，用数字说明有没有变好；AI 说"这样会更好"不算数。
3. **在报告里写明哪些部分用了 AI 帮助**（例如"降噪函数的初稿由 AI 生成，我们改了阈值并加了测试"）。如实写不扣分，不写被发现会扣分。
4. 只改本组文件；AI 建议你改别的文件时，先问老师。
