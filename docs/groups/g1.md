## 一、你们组负责什么

**一句话**：让流水线第 2 步"降噪与端点检测"在嘈杂、有长停顿的录音上切得更准，再用字错率说明识别有没有因此变好（没变好也如实写）。

- **对应步骤**：② 降噪与端点检测，基线代码在 `pipeline/step2_vad.py`。
- **槽位**：
  - `denoise`（降噪）：把录音里的背景噪声压低一些；
  - `vad`（端点检测）：找出录音里"哪几段有人在说话"，只把这些段落交给第 3 步识别。
  - 第 2 组在 `vad` 槽位也有自己的做法（叫 `g2`），写在他们自己的文件里，和你们互不影响。
- **你们的产出**：在 `pipeline/groups/g1_denoise.py` 里写出 `g1` 做法，在冻结的数据池版本上测出"**基础结果 + 改进后结果 + 对比数据**"，写成报告并答辩。
- **主要指标**：
  - 降噪前后的**字错率**，安静（Q）、嘈杂教室（N）、口袋/远距离（F）三种条件**分开看**；
  - **漏切人声**：该切出来的话没切出来（会变成字错率里的"漏字"）。
- **数据阶段（第 1—6 周）另外分管三件事**：
  1. 第 2 周：用全班试录的数据试定质检阈值（音量、静音），给老师一份建议；
  2. 第 3 周：对比安静和嘈杂录音的语谱图；排出全班 N 条件录音安排表和 N 条件说明；
  3. 第 4—6 周：组织全班的嘈杂教室（N）条件录音、安排补录、抽查全班 N 录音的质检结果。

## 五、基线做法是怎么工作的

### 5.1 第 2 步的整体流程

```
统一格式后的录音（16000 Hz 单声道）
   │
   ├─▶ 降噪 denoise      基线：原样返回，什么都不做          ← 第 1 组的槽位
   ├─▶ 远距离增强 enhance 基线：原样返回（第 2 组的槽位）
   └─▶ 端点检测 vad      基线：Silero VAD                    ← 第 1 组的槽位
          │
          ▼
   段落列表 [(开始秒, 结束秒), ...]
          │
          ▼
   第 3 步：用"降噪、增强后的声音"逐段识别成文字
```

`detect_speech()` 负责把这三步串起来。要注意两点：

- **识别用的是降噪后的声音**；但第 4 步说话人分离和第 7 步截取片段音频，用的仍然是原始录音（见 `pipeline/__init__.py`）。所以降噪只影响端点检测和识别；而你们切出的**段落时间**会一路传给后面各步。
- 降噪和增强**必须返回和输入一样长的采样**，否则时间轴会和原录音对不上。`detect_speech()` 会检查长度，长度变了就直接报错。

### 5.2 降噪（denoise）

- **基线 `denoise_baseline`**：原样返回。为什么默认不降噪？因为降噪不一定让识别更准——降噪可能把轻声说的字一起"削"掉，还可能留下一种叫"音乐噪声"的怪声。要用字错率验证过才能说它有用。
- **模板自带的备选做法 `denoise_noisereduce`**（默认不用）：调用 `noisereduce` 库的 `reduce_noise()`，做法叫"谱门限"：先估计每个频带的噪声大概有多大，再把低于这个门限的"时间—频率点"调小。可以想成：把语谱图上那一层灰蒙蒙的底色擦淡一点。

### 5.3 端点检测（vad）

**基线 `vad_baseline`**：用 Silero VAD（sherpa-onnx 提供的模型）。录音每 512 个采样（0.032 秒）一小块喂给检测器，检测器判断这一小块像不像人声；连起来就得到"从第几秒到第几秒有人说话"。参数在 `config.yaml` 的 `vad` 一节：

| 参数 | 默认值 | 意思 | 调大会怎样 | 调小会怎样 |
|---|---|---|---|---|
| `threshold` | 0.5 | 判断"有人声"要多大把握（0 到 1） | 更严格：轻声、远处的话可能被漏掉 | 更宽松：噪声也可能被当成人声 |
| `min_silence_duration` | 0.3 | 停顿超过多少秒才算一段话结束 | 段落更长、段数更少 | 段落更碎 |
| `min_speech_duration` | 0.25 | 连续有人声超过多少秒才算一段话 | 很短的"嗯""好"可能被丢掉 | 很短的杂音也可能被当成一段话 |
| `max_speech_duration` | 15 | 一段话超过多少秒后，在较短的停顿处切开 | 段落可能更长 | 长段讲解被切得更碎 |

注意 `max_speech_duration` 不是严格的上限：超过这个时长后会在更短的停顿处切开，但一直没有停顿时段落可能明显更长（见 `step2_vad.py` 的说明）。

### 5.4 为什么切得好不好会影响字错率

算字错率时，工具把一段录音里所有段落识别出来的文字按顺序拼起来，再和参考文本逐字对比：

- **漏切**（有人说话但没切出来）：这部分话根本没送去识别，就变成一串**漏字**。你们剧本里的"嗯""好"、G1-S2 里游客乙的轻声，最容易被漏掉。
- **多切**（把噪声、别组的说话声当成人声切出来）：识别器可能把噪声"听"成字，变成**多字**。
- **切在一个字中间**：前后两段的识别结果可能都不完整，变成**错字**或**漏字**。

所以看结果时，不能只看一个总的字错率，要把错字、漏字、多字拆开看。

### 5.5 本组文件现在的样子

`g1_denoise.py` 里已经登记好两个做法，现在都直接调用基线，所以第一天整个流程就能跑通：

```python
@register("denoise", "g1")
def denoise_g1(samples: np.ndarray, sr: int, cfg: dict) -> np.ndarray:
    return denoise_baseline(samples, sr, cfg)

@register("vad", "g1")
def vad_g1(samples: np.ndarray, sr: int, cfg: dict) -> list[tuple[float, float]]:
    return vad_baseline(samples, sr, cfg)
```

- `samples`：录音的采样，16000 Hz 单声道 float32，数值在 -1 到 1 之间；
- `sr`：采样率（16000）；
- `cfg`：整份配置（`config.yaml` 读进来的内容）。

**函数名、参数、返回值的格式都不要改**，只换函数体。

## 六、改进方向（由易到难）

先选 1—2 个方向做（方向 1—3 里选；方向 4 是选做），做透比做多重要。不管哪个方向，最后都要用字错率说话；**测出来没有变好也是有效结果**，如实写进报告。下面代码里的数值**只是举例，不代表会更好**，要你们自己试。

### 方向 1（最容易）：调端点检测参数 → 改 `vad_g1()`

**思路**：你们的剧本有很多一两个字的短回应、轻声说话和长停顿。可以试：`min_speech_duration` 调小一点，看短回应会不会被切出来；`threshold` 调低一点，看轻声会不会被切出来；同时注意会不会把噪声也切进来。

**怎么做**：

1. **先摸索**：在自己便携包的 `config.yaml` 里改 `vad` 一节，重启网页工具，在"整理录音"页传一段本组的 N 录音，看结果表格里短回应还在不在。
2. **正式做**：把选好的参数写进 `vad_g1()`，然后把 `config.yaml` **改回原值**。为什么？因为测评对比时，基线也读 `config.yaml`；你改了 `config.yaml`，基线也跟着变，对比表里的差值就成了 0。写法：

```python
@register("vad", "g1")
def vad_g1(samples: np.ndarray, sr: int, cfg: dict) -> list[tuple[float, float]]:
    """第 1 组的端点检测：沿用 Silero VAD，只换参数。"""
    my_cfg = dict(cfg)                       # 复制一份配置，不要直接改 cfg（后面的步骤还要用）
    my_cfg["vad"] = dict(cfg["vad"])         # vad 这一节也复制一份
    my_cfg["vad"]["min_speech_duration"] = 0.15   # 举例：更短的声音也算一段话
    my_cfg["vad"]["threshold"] = 0.45             # 举例：把握低一点也算人声
    return vad_baseline(samples, sr, my_cfg)
```

3. 写在 `vad_g1()` 里的参数不会出现在测评报告开头的"关键参数"一行，要在报告里自己写清楚，见 7.3 节的"注意"。

**怎么测**：`compare.py --slot vad --method g1`（见第七节）。字错率看 `compare_cer.md`；漏字、多字对照 `reports\g1\baseline\cer.md` 和改进后的 `cer.md`（`reports\g1\g1_vad_detail\cer.md`），重点看 N、F 条件有没有变化。

### 方向 2：用 noisereduce 降噪并调参数 → 改 `denoise_g1()`

**思路**：先用模板自带的 `noisereduce` 做法测一次（第 7 周），再在你们的函数里调它的参数。`noisereduce.reduce_noise()` 常用的参数：

| 参数 | 默认 | 意思 |
|---|---|---|
| `prop_decrease` | 1.0 | 把噪声压低多少（1.0 是全部压掉，0.5 是压掉一半）；压得太狠可能伤到轻声说的字 |
| `stationary` | False | True：认为噪声一直差不多（如发动机声、空调声）；False：认为噪声会变（如课间人声） |
| `y_noise` | 无 | 可以直接给一段"只有噪声"的声音，让它照着这段估计噪声（**只在 `stationary=True` 时才起作用**，`stationary=False` 时会被忽略） |

**怎么做**：

```python
@register("denoise", "g1")
def denoise_g1(samples: np.ndarray, sr: int, cfg: dict) -> np.ndarray:
    """第 1 组的降噪：noisereduce，调了参数。"""
    import noisereduce                       # 在函数里面导入（本组文件开头不要导入大的库）

    cleaned = noisereduce.reduce_noise(y=samples, sr=sr, stationary=True, prop_decrease=0.8)  # 数值是举例
    # 一定转回 float32；长度要和输入一样。
    # 全静音时 noisereduce 会除以 0 算出 NaN，NaN 会让端点检测误以为有人声，所以换成 0（和 step2_vad.py 一样）
    return np.nan_to_num(np.asarray(cleaned, dtype=np.float32), nan=0.0, posinf=0.0, neginf=0.0)
```

改完后 `denoise_g1()` 不再用 `denoise_baseline`，要把文件开头 import 里的 `denoise_baseline` 删掉（只留 `vad_baseline`），否则自动测试的代码检查会报"没用到的导入"。方向 3 同理。

**提示**：录音规范要求"开始录音后先安静 2—3 秒再开口"，所以录音开头那一小段基本只有背景噪声，可以试着把它当 `y_noise`（比如 `samples[: sr]`，开头 1 秒），**同时要设 `stationary=True`**。但要先听一下，确认开头真的没人说话。

**怎么测**：`compare.py --slot denoise --method g1`，三种条件分开看：在 N 上变好、在 Q 上变差，是很常见的情况。

### 方向 3：自己写谱减法 → 改 `denoise_g1()`

**思路**（经典的降噪方法，可以自己完整写出来，答辩时最好讲）：

1. 取录音开头约 1 秒（只有背景噪声）当"噪声样本"；
2. 把整段录音切成很多短帧，算出每帧的频谱（短时傅里叶变换）。可以用 `scipy.signal.stft`（便携包里有 scipy，`noisereduce` 要用它），也可以只用 numpy 的 `np.fft.rfft`；
3. 算出噪声样本里每个频率的平均幅度；
4. 每一帧的幅度减去"系数 × 噪声幅度"；减成负数的地方不要设成 0，而是留一个很小的下限（比如原幅度的一小部分），这样"音乐噪声"会少一些；
5. 保留原来的相位，逆变换回声音（`scipy.signal.istft` 或 `np.fft.irfft`）；
6. 截断或补零到**和输入一样长**，转成 float32 返回。

**要注意**：嘈杂教室的噪声是会变的（有人走动、说话），用开头 1 秒估出来的噪声不一定代表后面；这正好是你们可以在报告里分析的地方。系数和下限要试几组，每组都测一次字错率。

### 方向 4（最难，选做）：先估计信噪比，只对噪声大的录音降噪

**思路**：降噪在安静录音上可能帮倒忙。可以先估计"人声比噪声大多少"（信噪比），只对噪声大的录音降噪，安静的录音原样返回。

1. 用 `vad_baseline()` 找出有人声的段落，剩下的部分当作噪声；
2. 分别算人声部分和噪声部分的平均音量（均方根，换成分贝），两者相减就是粗略的信噪比；
3. 信噪比低于某个值才调用方向 2 或方向 3 的降噪，否则原样返回。

**要注意**：这个"某个值"如果是在同一份数据池上反复试出来的，结果可能偏乐观（相当于看了答案再定规则），报告的"局限"一节要写明。

      再对每段运行一次 `show_spectrogram.py`，把屏幕上的数字抄进表格。如果没有报静音，说明整段录音里没有一小段低于 `silence_dbfs`（噪声一直都在）。
   5. 再试着把 `silence_dbfs` 改成更高或更低几个数，看"最长静音"怎么变。
   6. 填一张**质检阈值建议表**：

      | 录音 | 听起来怎么样 | 整体音量（dBFS） | 最长静音（从第几秒、多长） | 现在的阈值报了什么 | 你们认为该不该报 |
      |---|---|---|---|---|---|

      最后写：建议三个阈值改成多少（或者不改），理由是什么，依据哪几段录音。
   7. 想一想你们自己的剧本：G1-S1、G1-S3 里有三到八秒的停顿，G1-S2 里有长达十秒的车内静默。长静音阈值要能抓住"空录、录音中断"，又不该把剧本里正常的停顿报成问题。音量阈值要能抓住真正太小声的录音，但不要把正常的口袋/远距离（F）录音一律报成"音量太小"。正式录音后（第 6 周）还要再检查一次。
   8. **试完把 `config.yaml` 改回原来的值**（用备份覆盖）。`config.yaml` 不是本组文件，最终阈值由老师决定、老师在入池用的电脑上改。

**本周交什么**：个人字错率作业；试录问题清单（每组一份）；**质检阈值建议表**（交给老师，第 4 周正式录音前定下来）。

## 十、常见坑

1. **改了 `config.yaml` 的 `vad` 参数，对比表差值却是 0**：测评时基线也读 `config.yaml`，你一改基线也跟着变。正式对比时把参数写进 `vad_g1()`（见第六节方向 1），`config.yaml` 改回原值。
2. **直接改了 `cfg`**：比如在 `vad_g1()` 里写 `cfg["vad"]["threshold"] = 0.4`，会悄悄影响后面所有步骤和下一段录音。先复制一份再改。
3. **降噪后长度变了**：`detect_speech()` 会报"把录音长度从……改成了……"。谱减法逆变换后要截断或补零到原长度。
4. **返回的数据类型、范围不对**：要返回 float32、数值在 -1 到 1 之间；不要换成整数采样。
5. **降噪"听起来干净"不等于识别更准**：可能把"嗯""好"、轻声说话一起压掉（漏字变多），也可能留下"音乐噪声"。一切以字错率为准。
6. **只看一个总数**：降噪可能在 N 上变好、在 Q 上变差，全体平均下来看不出来。Q、N、F 一定分开看。
7. **用了不同的数据池版本**：基线用 v1、改进用 v2，数字不能比。数据池升级了，基线和改进都要重跑。
8. **两次 `evaluate.py`（或两次 `compare.py`）用了同一个文件夹**：后一次的 `cer.md`/`cer.csv`（或 `compare_cer.md`/`compare_cer.csv`）会盖掉前一次。同一种工具每次用不同的子文件夹；一次 `evaluate.py` 和一次 `compare.py` 写的文件名不同，可以共用一个文件夹（如 `reports\g1\noisereduce`）。
9. **提交后自动测试有一项变红**：`tests/test_groups.py` 里有一项检查"各组初始做法和基线一样"（`test_audio_stubs_equal_baseline`），你们真正改了降噪以后，这一项很可能会失败，这是预料之中的。**不要去改这个测试文件**（不是本组文件），在 PR 说明或代交的 `说明.txt` 里写清楚，由老师处理。其他红叉要自己查原因；自动测试还会做代码检查，没用到的 `import` 没删也会报错。
10. **在文件开头导入大的库**：本组文件导入时不能加载 sherpa-onnx、gradio、tensorflow 等，`noisereduce`、`scipy` 也建议在函数里面导入。
11. **改了代码网页上没变化**：要关掉黑色窗口、重新双击 `start.bat`。
12. **文件保存成了别的编码**：用记事本保存时编码选 UTF-8，否则中文注释可能变成乱码，甚至运行报错。
13. **路径里有中文**：便携包、工作文件夹都放在纯英文路径（如 `D:\asr\tiandu`、`D:\asr\work`）。
14. **语谱图图片找不到、下次课没了**：`show_spectrogram.py` 画的图片在便携包的 `outputs\spectrograms\` 里，机房电脑会还原，下课前拷走。
15. **长停顿被当成"录音中断"**：本组剧本本来就有三到八秒、甚至十秒的停顿，定长静音阈值和看质检结果时要考虑到。
16. **为了字错率好看去改参考文本**：参考文本只跟着录音里人实际说的话走，绝对不能改成识别结果。
17. **机房电脑还原，东西没了**：每次下课前按"下课前拷走什么"拷到 U 盘。
18. **把录音交给在线工具或 AI**：不能把录音上传到在线降噪、在线转文字网站，也不能粘贴给 AI 工具；只能给 AI 看代码、报错和测评数字表格。
