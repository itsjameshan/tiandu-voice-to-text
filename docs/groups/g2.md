## 五、基线做法是怎么工作的

第 ② 步有三个槽位，**按顺序**执行：

```
转好格式的录音（16000Hz 单声道）
  │
  ├─▶ 降噪 denoise（第 1 组；基线：原样返回）
  ├─▶ 远距离增强 enhance（你们组；基线：原样返回，什么都不做）
  └─▶ 端点检测 vad（基线：Silero VAD）──▶ [(开始秒, 结束秒), (开始秒, 结束秒), ...]

处理过的声音 ──▶ 第 ③ 步：把每一段识别成文字
原始的声音   ──▶ 第 ④ 步说话人分离、第 ⑦ 步剪疑似片段（这两步不用处理过的声音）
```

把三个槽位串起来的是 `detect_speech` 函数。它会检查：降噪和增强**返回的采样点个数必须和输入一样**，不一样就报错——因为后面的时间戳要和原录音对得上。

**远距离增强（`enhance_baseline`）**：原样返回。也就是说，"基线的 F 字错率"就是现在的识别模型直接听口袋/远距离录音的结果。

**端点检测（`vad_baseline`）**：用 Silero VAD 判断"哪几段有人在说话"，只把这些段交给识别。录音按每 512 个采样（0.032 秒）一小块喂给检测器。参数在 `config.yaml` 的 `vad` 一节：

| 参数 | 意思 | 默认 |
|---|---|---|
| `threshold` | 判断"有人声"的把握（0 到 1），越大越严格 | 0.5 |
| `min_silence_duration` | 停顿超过多少秒才算一段话结束 | 0.3 |
| `min_speech_duration` | 连续有人声超过多少秒才开始算一段话 | 0.25 |
| `max_speech_duration` | 一段话超过多少秒后，就在较短的停顿处切开 | 15 |

**你们的两个函数**（现在都直接调用基线）：

- `enhance_g2(samples, sr, cfg)`：输入、输出都是 16000Hz 单声道 float32 采样（数值在 -1 到 1 之间），**长度必须相同**。
- `vad_g2(samples, sr, cfg)`：返回 `[(开始秒, 结束秒), ...]`，按时间先后排列。

**为什么 F 条件更难**（第 3 周看语谱图时对照着理解）：

1. **声音小**：离得远或隔着衣服，整体音量变小，端点检测可能把小声的话当成"没人说话"漏掉——漏掉的话在字错率里就是**漏字**。
2. **发闷**：衣服布料挡住了高频，语谱图上半部分（高频）明显变淡（颜色变浅），"s、sh、c、ch"这类声音变模糊——识别时容易变成**错字**。
3. **远近交替**：贴着口袋的耳语很响，房间另一头的店员很轻，同一段录音里音量忽大忽小。
4. **杂音**：手碰手机、衣服摩擦的声音，可能被当成人声切出来，识别出乱字——就是**多字**。

## 六、改进方向（由易到难）

**原则**：方向 1—3 是主要的，方向 4、5 选做；一次只改一个地方、测一次；每个改进都要在 Q、N、F 三种条件上测，**F 变好了、Q 却变差了也要写进报告**。尽量只用 numpy（便携包里已经有）；想用别的库先问老师——便携包里没有的库，别的电脑上也运行不了。

### 方向 1（最容易）：音量归一化 —— 改 `enhance_g2`

- **思路**：把整段录音的音量调到差不多 -20 dBFS（dBFS 是数字音量的单位，0 是最大，越负越小）。
- **步骤**：
  1. 算整段的平均音量（均方根）：`rms = np.sqrt(np.mean(samples ** 2))`，换成 dBFS：`20 * np.log10(rms)`（`pipeline/step1_ingest.py` 里的 `_dbfs` 就是这样算的）。
  2. 算要放大多少倍：`gain = 10 ** ((-20 - 当前dBFS) / 20)`，乘上去。
  3. 乘完检查最大绝对值：到了 1 就会削波（质检把达到 `CLIP_LEVEL` 0.999 的点算作削波）。超过时把 `gain` 调小，让最大值留在 1 以下。
  4. 整段都是静音（`rms` 为 0）时直接原样返回，别除以 0。
- **注意**：识别模型对音量大小不一定敏感，这个方向可能变化很小——**测出来没变化也是结论**，如实写。

### 方向 2：提升高频（预加重或简单均衡）—— 改 `enhance_g2`

- **思路**：口袋录音"发闷"是高频被挡掉了，把高频提起来一些。
- **预加重**（最简单）：`pipeline/features.py` 第 139 行左右就有一行现成的写法 `np.append(x[:1], x[1:] - 0.97 * x[:-1])`，长度不变。预加重会让整体音量变小，做完再接方向 1 的音量归一化。
- **简单均衡**：用 `np.fft.rfft` 把整段变到频率上，把某个频率以上的部分乘一个大于 1 的数，再用 `np.fft.irfft(..., n=len(samples))` 变回来（一定要写 `n=len(samples)`，长度才不变）。从哪个频率开始提、提多少，试两三组值。
- **注意**：高频的嘶嘶声、衣服摩擦声也会一起被放大。处理完画一张语谱图看看上半部分颜色是不是变深了（见第七节 7.1）。

### 方向 3：调端点检测参数 —— 改 `vad_g2`

- **思路**：远距离的人声能量低，Silero VAD 可能"没把握"而漏切。把 `threshold` 调低一点，减少漏切；耳语很短，也可以试 `min_speech_duration` 调短一点。
- **怎么写**（不要改 `config.yaml`，在本组文件里复制一份配置再改）：

  ```python
      # vad_g2 函数里面这样写（def 那一行不要改）
      my_cfg = dict(cfg)                                  # 先复制一份，不要直接改 cfg
      my_cfg["vad"] = dict(cfg["vad"], threshold=0.4)     # 只改端点检测的 threshold，多试几个值
      return vad_baseline(samples, sr, my_cfg)
  ```

- **注意**：阈值太低会把杂音也切成"人声"，识别出乱字，**多字**会变多。对比时看 `cer.csv` 里漏字和多字分别怎么变。`vad_g2` 对所有录音都起作用，Q、N 也会变。

### 方向 4（选做）：动态范围压缩 —— 改 `enhance_g2`

- **思路**：把小声的部分放大、大声的部分压一压，对付"耳语很响、店员很轻"这种远近交替。
- **步骤**：
  1. 把录音切成小段（比如质检用的 0.1 秒一段），算每段的音量；
  2. 每段算一个增益：越小声放大越多，但**要设上限**，否则纯静音和底噪也会被放得很大；
  3. 相邻小段的增益要平滑过渡（例如用 `np.interp` 把每段的增益铺到每个采样点上），否则会听到"咔咔"声；
  4. 最后做一次方向 1 的检查，别削波。
- **注意**：参数多，最难调。先在一两段录音上听效果（7.1），再跑全班。

### 方向 5（选做，进阶）：先判断，再处理 —— 改 `enhance_g2`

- **思路**：增强对 F 有用，对 Q 可能有害。那就先从声音本身判断"像不像口袋/远距离录音"（比如整体音量低、高频能量占比小），像才处理，不像就原样返回。
- **注意**：
  - **不能靠文件名判断**。函数本来就拿不到文件名；真实使用时也没有人告诉你这是哪种条件。
  - 判断的标准是你们看了全班录音以后定的，报告里要如实写"标准是怎么定的、在哪些录音上试过"。

### 7.4 怎么看结果

1. **字错率** =（错字 + 漏字 + 多字）÷ 参考文本字数，越低越好（见[测评指南](../guides/evaluation.md)第一节）。测评用的是测评模式（数字是汉字读法），和参考文本口径一致。
2. **三种条件的差距**：在 `cer.md` 的按条件汇总里找 Q、N、F 三个字错率，算 **F − Q** 和 **N − Q**。`cer.md` 里的字错率写成小数（如 0.1234 即 12.34%）：先乘 100 换成百分数再相减，差值的单位叫"百分点"（例：F 0.3456、Q 0.1234 → F − Q = 34.56% − 12.34% = 22.22 个百分点）。基线算一次、改进后算一次，填进报告：

   | （填百分数） | Q | N | F | N − Q | F − Q |
   |---|---|---|---|---|---|
   | 基线 | | | | | |
   | 改进（g2） | | | | | |

3. **对比表**（`compare_cer.md`）：每行一个分组项（全体、Q、N、F……），列出基线、改进、差值。**重点看 F 那一行有没有降低，同时看 Q、N 有没有变差。**
4. **成对比较**：用 Excel 打开 `cer.csv`，把同一个剧本的 Q 和 F 放在一起比（如 G2-S1-Q 和 G2-S1-F）。台词基本一样、只是手机位置不同，差距更能说明问题。全班有 24 对。
5. **口袋和远距离分开看**：用 Excel 打开 `cer.csv`，先"另存为" `reports\g2\cer_F_split.xlsx`（Excel 工作簿），在这个副本里按第 5 周的"全班 F 录音记录汇总表"加一列"口袋/远距离"再分开算；`cer.csv` 本身不要改、不要保存。自己用 Excel 算时，用"错字 + 漏字 + 多字之和 ÷ 参考文本字数之和"，不要把每段的字错率直接平均（两种算法结果不一样，报告里写清楚用的哪种）。
6. **拆开看错在哪**：F 的漏字特别多 → 多半是声音太小、端点检测漏切（试方向 3）；错字特别多 → 多半是发闷（试方向 2）；改了以后多字变多 → 可能把杂音也切进来了。

## 十、常见坑

1. **两条 `compare.py` 写进同一个文件夹**：`compare_cer.md` 会被后一条覆盖。每条命令用不同的 `--out`（远距离增强用 `reports\g2`、端点检测用 `reports\g2\vad`，和报告模板一样）。
2. **改了 `config.yaml` 的端点检测参数**：基线也跟着变了，对比就没有意义。参数写在 `vad_g2` 里（第六节方向 3）。
3. **采样点个数变了**：程序报错"必须返回同样长度的采样"。预加重用 `np.append(x[:1], ...)`，`irfft` 一定写 `n=len(samples)`。
4. **放大过头削波**：最大绝对值到了 1，声音被削平，字错率反而变差。先算好增益再乘，别只靠截断。
5. **噪声也被放大**：静音、底噪、衣服摩擦声一起变大，端点检测多切，**多字**变多。看 `cer.csv` 里多字的变化。
6. **只看 F 不看 Q**：增强对所有录音都起作用，Q 可能变差。三种条件都要看。
7. **用文件名判断条件**：函数拿不到文件名，真实使用时也没人告诉你条件，不要想办法绕过去。
8. **F 录音质检报"音量太小"就把手机挪近重录**：那就不是 F 了。只有真的录坏了才重录，和老师商量。
9. **F 录音校对时照着识别结果改参考文本**：参考文本只跟着录音里人说的话走。听不清就保留剧本原文、写备注。
10. **测评跑一半电脑重启或休眠**：全班录音约 5 小时，跑得很久。课外开着跑，别关黑色窗口。中断了再运行同一条命令会接着测（已识别的有缓存；数据池是只读共享文件夹时不留缓存，要从头再测，见 7.3）。
11. **机房电脑还原**：`g2_far_field.py` 和 `reports\g2\` 每次下课都拷到 U 盘，下次上课先拷回来。
12. **个人字错率作业把阿拉伯数字算成错字**：网页显示的是显示模式（"2800"），测评工具用的是测评模式（"两千八百"）。手算时按读法比。
13. **自动测试 `tests/test_groups.py` 有一项变红**（如 `test_audio_method_returns_samples[enhance-g2]`）：这一项检查的是本组函数**返回的格式**（类型、长度、时间范围、类别名），不检查和基线一样不一样：改进以后结果和基线不同是正常的，不会因此变红。变红说明返回的格式错了（看红叉下面的中文说明，例如"返回了不合理的片段"），流程后面的步骤会出错，要改好本组文件再提交；**不要去改这个测试文件**（不是本组文件）。其他红叉也要自己查原因；自动测试还会做代码检查，没用到的 `import` 没删也会报错。
14. **用了便携包里没有的库**：在自己电脑上能跑，别人的便携包里跑不了。尽量只用 numpy。
15. **把录音发给 AI 工具或用微信、QQ 传录音**：违反红线。给 AI 看代码和测评数字可以，录音不行。
16. **客串的同学没签同意书**：客串的同学录音前也要签。
17. **客串的人每次不一样**：同一个角色换了人，三种条件就不好比了。尽量固定同一位第 1 组同学。
