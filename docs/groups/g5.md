## 一、你们组负责什么

**一句话**：识别模型不认识我们虚构的旅行社名、店名和云南的地名、行话，常常写成同音的别字（"雾隐行舟旅行社"→"雾影行走旅行社"）。你们要让这些**专名**识别得更准，同时**不能过度纠正**——剧本里人物故意说错或简称的名字（如把"松风晚渡"说成"松风行舟"），工具要照实记录，不能"改对"。最后用"专名正确率"和"过度纠正次数"两个数说明有没有变好（没变好也如实写）。

- **对应步骤**：③ 语音识别与热词。识别用的是模板自带的 SenseVoice 模型（`pipeline/step3_asr.py`，你们不改）；识别完以后的**热词纠错**基线在 `pipeline/hotwords.py`。
- **槽位**：`hotword`（热词纠错）。这一步拿到识别出来的段落，把"读音像热词、字写错了"的地方换成热词表里的正确写法，同时改两个字段：
  - `text`：显示模式的文字（带标点、阿拉伯数字），给网页和 Word 初稿用；
  - `text_raw`：测评模式的文字（汉字读法、没有标点），**算专名正确率、字错率用的就是它**；
  - 每改一处，记一条进段落的 `corrections`（"原来的字 → 热词"），导出的表格里有一列"热词纠错"，复核的人能看到工具改了哪里。
- **为什么重要**：核查初稿里"提到了哪家旅行社、哪家店"是工作人员最先要核对的。名称写成别字，核对就要多花时间；可要是把游客口误的名字"改对"了，又等于替人说了没说过的话。所以两头都要顾到，而且不管多准，都**必须人工对照原声复核**。
- **你们的产出**：在 `pipeline/groups/g5_hotwords.py` 里写出 `g5` 做法，测出"**基础结果 + 改进后结果 + 对比数据**"，写成报告并答辩。
- **主要指标**（`tools/evaluate.py hotwords`）：
  - **专名正确率**：参考文本里出现的热词（`data/hotwords.txt` 里的虚构旅行社、店名、地名、行话），在识别结果里也出现了的比例。越高越好。
  - **过度纠正次数**：参考文本里人物**故意说错或简称**的名字（`data/hotword_variants.csv`），被热词纠错改掉（改成正确名称或它的简称）的次数。越少越好。具体怎么数见第五节 5.5。
  - 两个数**一定要一起看、一起报告**，只看一个会误导。另外顺便看"热词纠错次数"和字错率。
  - 安静（Q）、嘈杂教室（N）、口袋或远距离（F）三种条件分开报告。
- **数据阶段（第 1—6 周）另外分管一件事**：抽查全班 72 份参考文本里虚构名称、行话的写法，记录实际说错或简称的地方（第 5 周开始抽查，第 6 周继续抽查并汇总问题）。这件事直接决定你们第 7 周以后测出来的"过度纠正"可不可信，见第五节 5.6。

## 五、基线做法是怎么工作的

### 5.1 热词纠错在流水线里的位置

```
第 2 步切出有人声的段落 ──▶ 第 3 步 SenseVoice 识别 ──▶ 热词纠错（hotword）  ← 第 5 组的槽位
                                                         │  改 text 和 text_raw，记下 corrections
                                                         ▼
                              第 4 步说话人分离 ──▶ 第 5 步数字规范化 ──▶ 第 6 步话术分类 ──▶ ……
```

**为什么是"识别以后再纠错"**：真正的热词功能是在识别的过程中（"解码时"）就告诉模型"这几个词更可能出现"。可是 sherpa-onnx 里的 SenseVoice 模型不支持解码时热词，所以基线只能等识别完，再按**拼音**去找、去换。这也意味着：识别得太离谱（比如口袋录音里名称糊成一团、字数都不对），拼音纠错就救不回来。

**两种文字**：同一段话识别两种写法。网页"整理录音"页平时只用显示模式（`text`）；测评命令用测评模式（`text_raw`）。基线对两个字段都纠错，所以网页上能看到效果，测评也能测到效果。

### 5.2 基线一步一步做什么（`correct_text`）

1. **挑热词**：从 `data/hotwords.txt` 里只挑 **3 个字以上、全是汉字**的名称（参数 `min_len`，默认 3）。两个字的（"杨导""束河""冰种"）和带字母的（"A货""B区"）先不用，因为太容易把普通的话误改。
2. **转成"模糊拼音"**（`fuzzy_pinyin`）：用 pypinyin 把字转成不带声调的拼音（一串字一起转，多音字能按词读对），再把容易混的音归成一个：
   - 声母：zh→z、ch→c、sh→s，开头的 l→n；
   - 韵母：ing→in、eng→en、ang→an。

   例如"雾影行走"→ wu yin xin zou，"雾隐行舟"→ wu yin xin zou，两个一样。
3. **从左往右逐字找**：只在连续的汉字里找（标点、空格、数字、字母会把汉字隔开）。在每个位置先试长的热词、再试短的，取和热词一样长的一段字：
   - 字面和热词完全一样：本来就对，不改，跳过这几个字；
   - 字面不同，但模糊拼音逐个音节比，对不上的音节数 ≤ `max_syllable_mismatch`（默认 0，就是必须全对上）：换成热词，记一条 `{"from": 原来的字, "to": 热词}`，跳过这几个字；
   - 都不是：保留这个字，往后挪一个字。
4. **开关**（`hotword_baseline`）：`config.yaml` 里 `hotword.enabled` 默认是 `false`，**关着的时候什么都不做**，原样返回。网页"整理录音"页有"热词纠错"开关；测评命令用 `--hotword on` / `--hotword off` 临时打开、关闭。
5. 打开时，对每个段落的 `text` 和 `text_raw` 都纠错；同一处替换在两个字段里只记一次；记录写进段落的 `corrections`，每条多记一个 `start`（段落开始时间），方便对照录音。

### 5.3 两个参数是一把"松紧钮"

| 参数 | 默认 | 调松一点会怎样 | 调紧一点会怎样 |
|---|---|---|---|
| `min_len`（只用几个字以上的热词） | 3 | 改成 2：两个字的名称（"杨导""束河"）也能纠了，但普通的话也会被误改 | 改成 4：更少误改，但"翠微坊""听松阁""古树茶"这样三个字的名称不管了 |
| `max_syllable_mismatch`（允许几个音节对不上） | 0 | 改成 1：差一个音的错法也能纠了，但故意说错的名字也可能被"改对"（过度纠正） | 已经是最紧了 |

### 5.5 指标是怎么数的（`tools/evaluate.py hotwords`）

测评工具对数据池里每段录音：识别（测评模式，有缓存就用缓存）→ 用你指定的做法热词纠错 → 把纠错后的 `text_raw` 和参考文本比。比之前两边都先去掉标点和空格、全角转半角、字母转大写。

**专名正确率**：
1. 先把两边文字里 `data/hotword_variants.csv` 的说错、简称说法"挖掉"（这些位置不算专名）；
2. 从左往右数每个热词出现几次，同一个位置长短几个名称都对得上时只算最长的（"雾隐行舟旅行社"不再另算"雾隐行舟"和"雾隐"）；
3. 每个名称的命中次数 = min（参考文本里的次数，识别结果里的次数）；
4. 专名正确率 = 命中次数之和 ÷ 参考文本里的专名次数之和。

例：参考文本是"我是雾隐行舟旅行社的老导游……在雾隐行舟带团"，专名 2 次（"雾隐行舟旅行社"1 次、"雾隐行舟"1 次）。识别结果是"我是雾影行走旅行社的老导游……在雾隐行舟带团"：命中 1 次，专名正确率 = 1 ÷ 2 = 50%。纠错把"雾影行走旅行社"改对以后，命中 2 次，100%。

**过度纠正次数**：按正确名称分别数。先数参考文本里这个正确名称的各种说错、简称说法一共出现几次，记作 n。再用下面两种办法各数一遍，**取大的那个，但最多记 n 次**：

- **办法 A：被纠错改掉的说错名称**。每种说错、简称的说法，参考文本里有 r 次，纠错**之前**的识别文字里有 b 次，纠错**之后**还剩 a 次，记 min（r，b）− a 次（小于 0 记 0），几种说法加起来。意思是：人说错了，识别也照实写出来了，热词纠错却把它改掉了——**不管改成了什么**都算。
- **办法 B：多出来的正确名称**。数这个正确名称的"一家"在纠错之后的识别文字里比参考文本里多出几次（小于 0 记 0）。"一家"是正确名称本身，加上热词表里是它的一部分、又不在它的说错说法里的简称：
  - "听松阁玉器行"一家还有"听松阁"；
  - "雾隐行舟旅行社"一家还有"雾隐行舟"；
  - "松风晚渡旅行社"一家还有"松风晚渡"；
  - "百年茶语"一家还有"茶语"；
  - "晓月银坊"一家只有它自己（"晓月"也在说错的"晓月阁"里，不算）。

  为什么简称也要算：热词纠错只能把一段字换成**一样长**的热词，说错的"听松坊"（3 个字）只会被改成"听松阁"，不会变成"听松阁玉器行"。

例 1：参考文本里游客乙说"百年茶叶这牌子没听说过"（n = 1）。识别照实写成"百年茶叶"，纠错把它改成了"百年茶语"。办法 A："百年茶叶"纠错前 1 次、纠错后 0 次，记 1 次；办法 B："百年茶语"一家比参考文本多出 1 次，也是 1。取大的，过度纠正记 1 次。

例 2：参考文本里是"回头去那个听松坊"（n = 1），识别也写成"听松坊"，纠错（参数放松以后）把它改成了"听松阁"。办法 A："听松坊"被改掉了，记 1 次；办法 B："听松阁"是"听松阁玉器行"一家的，多出 1 次，也是 1。过度纠正记 1 次。

还要知道：识别时就把说错的名称写成了正确名称（没经过纠错），办法 B 也会算进去，所以热词纠错关的那次测评，过度纠正也可能不是 0。第 7 周看到 `reports\g5\off` 里过度纠正不是 0，不要奇怪，那多半是识别本身带来的，不是纠错带来的；纠错带来多少，要拿开、关两次比。

报告 `hotwords.md` 开头会写这些数法和数据池版本；后面有三张表：汇总（全体、按录音条件、按组）、各专名的命中情况（错得多的排前面）、过度纠正明细（按正确名称）。

### 5.6 这个指标的三个"盲点"（一定要知道）

1. **只数变体表里有的说法**：演员即兴说错的名字（比如把"翠微坊"说成了"翠微阁"），如果没写进 `data/hotword_variants.csv`，工具就不知道那是"说错"的。纠错（比如参数放松以后）把它改成"翠微坊"，**测不出过度纠正**；参考文本里写的是"翠微阁"，它也不算专名，专名正确率也不受影响（只有字错率里多一个错字）——等于这个错误被藏起来了。
2. **误改普通的话不算过度纠正**：过度纠正只数变体表里说错、简称的名字。纠错把普通的话改成了热词（"团队里"→"团队价"、"打理"→"大理"），过度纠正里一点也看不出来，只会让"热词纠错次数"变多、字错率变高。所以除了看数字，还要用第七节 7.4 的小工具**亲眼看纠错记录**。
3. **过度纠正是按次数估算的，没有逐字对齐**：工具只比"次数"，不一个字一个字地对位置。在同一段录音里，一处正确名称被识别错了（正确名称少了 1 次），另一处说错的名称又被"改对"了（正确名称多了 1 次），办法 B 里这两处会**互相抵消**；办法 A 能补上一部分，但不一定都数得到。所以次数小的时候（差 1、2 次），一定要用 7.4 的小工具找到那几处，**对照原声**确认。

盲点 1 就是你们数据阶段分管项的意义：**把全班录音里实际说错、简称的地方都找出来、记下来**，交给老师决定要不要补进变体表；补不进去的，你们在报告里手工统计、如实写明。盲点 2、3 要靠第七节 7.4 的小工具和纠错例子表补上。

### 6.0 先搭好架子（所有方向都用这个写法）

把 `g5_hotwords.py` 里开头说明文字下面的全部代码（`from pipeline.hotwords import hotword_baseline`、`from pipeline.methods import register` 两行和 `hotword_g5` 函数）整个换成下面这样（**开头的说明文字保留，不要删**；原来那两行 `import` 不要留着，否则 `register` 导入了两次、`hotword_baseline` 导入了却没用，自动测试的代码检查会报错，而下面那条 `python -c` 检查命令查不出这种错）。它和基线做的事完全一样，只是把参数放进了本组文件、留好了"保护名单"的位置：

```python
import re
from collections import Counter

from pipeline.data import load_hotwords
from pipeline.hotwords import correct_text
from pipeline.methods import register

# ===== 第 5 组自己的参数（只在 g5 里用，不影响基线）=====
MIN_LEN = 3         # 只用几个字以上的热词（基线默认 3）
MAX_MISMATCH = 0    # 模糊拼音最多允许几个音节对不上（基线默认 0）
PROTECT_WORDS = []  # 保护名单：这些词原样保留，不参加纠错（方向 2 再往里填）


def correct_g5(text: str, hotwords: list[str]) -> tuple[str, list[dict]]:
    """第 5 组的纠错：保护名单里的词先切出来原样保留，其余部分交给基线的 correct_text。"""
    pieces = [text]  # 没有保护名单时，整段文字就是一块
    if PROTECT_WORDS:
        # 长的保护词先匹配；re.split 的规则里加了括号，切开后奇数位置就是保护词本身
        pattern = "(" + "|".join(re.escape(w) for w in sorted(PROTECT_WORDS, key=len, reverse=True)) + ")"
        pieces = re.split(pattern, text)
    out, records = [], []
    for i, piece in enumerate(pieces):
        if i % 2 == 1:
            out.append(piece)  # 保护词：原样保留
            continue
        fixed, found = correct_text(piece, hotwords, MIN_LEN, MAX_MISMATCH)
        out.append(fixed)
        records.extend(found)
    return "".join(out), records


@register("hotword", "g5")
def hotword_g5(segments: list[dict], hotwords: list[str] | None, cfg: dict) -> list[dict]:
    """第 5 组的热词做法。hotwords 为 None 时用 data/hotwords.txt。"""
    settings = cfg.get("hotword") or {}
    if not settings.get("enabled"):
        return segments  # 和基线一样：热词纠错开关关着就原样返回
    if hotwords is None:
        hotwords = load_hotwords()
    result = []
    for seg in segments:
        seg = dict(seg)  # 复制一份再改，不改传进来的段落
        records = []
        counted = Counter()  # text 和 text_raw 里的同一处替换只记一次（照抄基线的写法）
        for field in ("text", "text_raw"):
            if not seg.get(field):
                continue
            seg[field], found = correct_g5(seg[field], hotwords)
            for item in found:
                pair = (item["from"], item["to"])
                if field == "text":
                    counted[pair] += 1
                elif counted[pair] > 0:
                    counted[pair] -= 1
                    continue  # text 里已经记过这一处
                records.append({"from": item["from"], "to": item["to"], "start": seg.get("start")})
        if records:
            seg["corrections"] = list(seg.get("corrections") or []) + records
        result.append(seg)
    return result
```

**思路**：方向 1 会发现"一松就乱改"。那就**松的只给不容易误伤的地方**：

**2a. 常用词保护名单**：把方向 1 里被误改的**普通的话**放进 `PROTECT_WORDS`（例如"行程表""团队里""桌子""饮食"），它们原样保留、不参加纠错。

```python

```

> ⚠️ **不要把 `data/hotword_variants.csv` 里的说法（"松风行舟""听松坊"……）抄进保护名单**。那是测"过度纠正"的考题，抄进去等于看着答案答题：过度纠正会变成 0，但什么也说明不了，答辩也讲不过去。

**2b. 长名称放松、短名称收紧**：五个字以上的完整名称（"翠微坊珠宝店""松风晚渡旅行社"）和普通的话撞车的可能小，可以允许差一个音；三四个字的照旧按 `MIN_LEN`、`MAX_MISMATCH`（默认 3、0，也就是必须全对上）。把一次纠错拆成两遍：

```python
LONG_LEN = 5  # 几个字以上算"长名称"


def correct_by_length(text: str, hotwords: list[str]) -> tuple[str, list[dict]]:
    """第一遍：只用长名称，允许差 1 个音；第二遍：照 MIN_LEN、MAX_MISMATCH 用全部热词。"""
    long_words = [w for w in hotwords if len(w) >= LONG_LEN]
    text, first = correct_text(text, long_words, LONG_LEN, 1)
    text, second = correct_text(text, hotwords, MIN_LEN, MAX_MISMATCH)
    return text, first + second
```

再把 `correct_g5` 里的 `fixed, found = correct_text(piece, hotwords, MIN_LEN, MAX_MISMATCH)` 换成 `fixed, found = correct_by_length(piece, hotwords)`。例如"翠微坊珠宝站"在默认参数下不改，用这个办法会改成"翠微坊珠宝店"，而"团队里""行程表"不会被误改（用 7.6 的命令自己验证）。

**怎么测**：和方向 1 一样跑 `evaluate.py hotwords --method hotword=g5 --hotword on`，再用 7.4 的小工具看改了什么。

### 方向 3：两个字的热词，要看前后文

**思路**：基线完全不管两个字的名称（"杨导""束河""喜洲""生普""熟普""冰种""糯种"），可这些词在本组剧本里很多。直接把 `MIN_LEN` 改成 2 会乱改（"桌子"→"镯子"）。办法是：**两个字的热词只有在前后几个字里出现"提示词"时才换**。比如"生普""熟普"附近常有"茶""饼"，"束河""喜洲"前面常有"去""到""在"。

```python
from pipeline.hotwords import fuzzy_pinyin

# 两个字的热词：只有前后 4 个字以内出现提示词，才允许替换（举例，按你们第 2、7 周看到的错法来填）
CONTEXT_WORDS = {
    "生普": ["茶", "熟普", "饼"],
    "熟普": ["茶", "生普", "饼"],
    "束河": ["去", "到", "在"],
}


def fix_two_char(text: str) -> tuple[str, list[dict]]:
    """第二遍：只纠 CONTEXT_WORDS 里两个字的热词，而且前后 4 个字以内要有提示词。"""
    chars = list(text)
    pinyin = fuzzy_pinyin(text)  # 每个字一个拼音
    records = []
    for i in range(len(chars) - 1):
        window = "".join(chars[i:i + 2])
        for word, hints in CONTEXT_WORDS.items():
            if window == word or pinyin[i:i + 2] != fuzzy_pinyin(word):
                continue  # 本来就对，或者读音对不上
            around = text[max(0, i - 4):i + 6]  # 这两个字和前后各 4 个字
            if any(hint in around for hint in hints):
                chars[i:i + 2] = list(word)
                records.append({"from": window, "to": word})
                break
    return "".join(chars), records
```

在 `correct_g5` 里，`fixed, found = correct_text(...)`（做了方向 2b 的话是 `correct_by_length(...)`）这一行后面加两行：`fixed, more = fix_two_char(fixed)` 和 `found = found + more`。用 7.6 的命令试一试："这个是身铺还是熟普啊"应该变成"生普"，"明天去蜀河"应该变成"束河"，"他身铺了一层"（附近没有提示词）不应该变。

**要注意**：
- 提示词要按"一类说法"想，不要针对某一句台词写死；剧本上效果好，换一段录音可能就不行，写进局限。
- 两个字的名称里，"杨导"这样的称呼很常见，但"羊""洋"也很常见，先拿 7.6 的命令多试几句普通的话再决定放不放。
- 用了 `fuzzy_pinyin` 就要在文件开头加 `from pipeline.hotwords import fuzzy_pinyin`；没用到的 `import` 要删掉，否则自动测试的代码检查会报错。

### 7.3 怎么看结果

`evaluate.py hotwords` 在 `--out` 文件夹里写出 `hotwords.md`（汇总报告）和 `hotwords.csv`（每段录音一行）。`compare.py` 写出 `compare_hotwords.md`、`compare_hotwords.csv`（和 `compare_cer.*`）：每行一个分组项（全体、Q、N、F、各组），列出基线、改进、差值（差值 = 改进 − 基线）。这张表直接放进报告的"对比表"一节；报告开头会自动写明数据池版本、做法和关键参数。注意：报告开头"关键参数"写的是 `config.yaml` 里基线用的 `min_len`、`max_syllable_mismatch`，不是你们文件里的 `MIN_LEN`、`MAX_MISMATCH`（`LONG_LEN`、`PROTECT_WORDS` 也不会写进去）；你们自己的参数一定要写进参数试验表和报告。

看的时候：

1. **两个数一起看**：专名正确率的差值为正、过度纠正的差值为负，才是两头都变好。一个变好、一个变差，就要权衡、讨论，不能只报好的那个。
2. **再看"热词纠错次数"和字错率**：纠错次数多了很多、字错率反而上去了，多半是在乱改普通的话。
3. **三种条件分开看**：口袋或远距离（F）的录音识别得差，名称可能错得面目全非，拼音纠错不一定救得回来；很多改进只在某一种条件下有用。
4. **看"第 5 组"那一行**：故意说错的说法几乎都在本组剧本里，过度纠正主要看这一行。
5. **看"各专名的命中情况"表**：错得多的排前面，哪些名称最该下功夫一目了然；再看看它们被识别成了什么（用 7.4 的小工具或"数据校对"页的对照）。
6. **次数少时别急着下结论**：过度纠正的次数一般很小，差 1、2 次可能只是一两句话的事。到 7.4 的小工具里把这几处找出来，听原声确认。
7. **记住 5.6 的三个盲点**：变体表里没有的说错数不到；误改普通的话不算过度纠正；过度纠正是按次数估算的，没有逐字对齐。报告里要把你们亲眼看到的这类情况另外写出来。

```python
    out = hotword_g5([seg], None, cfg)
    assert out[0]["text_raw"] == "我们报的是雾隐行舟旅行社"
    assert out[0]["corrections"][0]["to"] == "雾隐行舟旅行社"
    assert seg["text_raw"] == "我们报的是雾影行走旅行社"  # 传进来的段落没有被改


def test_g5_keeps_common_words():
    cfg = load_config(overrides={"hotword": {"enabled": True}})
    seg = {"start": 0.0, "end": 1.0, "speaker": "游客甲", "label": "",
           "text": "放在桌子上", "text_raw": "放在桌子上"}
    assert hotword_g5([seg], None, cfg)[0]["text_raw"] == "放在桌子上"
```

   - 第 4 组的数字规范化在你们后面做：热词表里的名称在第 5 步会被整个保护起来（如"百年茶语"的"百"不会被转成数字），可要是名称被识别成了别字，就保护不到了；
   - 第 6、7 组的话术分类用的是纠错后的文字，名称改对或改错，都可能影响分类（比如多出误报），全班测试时和第 6、7、8 组一起留意；
   - 你们改错的名称，会出现在核查初稿和导出表格里，复核的人要对照原声确认（"热词纠错"一列就是给他们看的）。
6. 某个地方报错：只改本组文件，修好后重新提交。
7. **定稿报告**：按模板把每一节写完整，特别是"结论与局限"：剧本数据上的测评结果不代表真实场景；专名正确率和过度纠正哪个变好、哪个变差；Q、N、F 有什么不同；第五节 5.6 的指标盲点（变体表里没有的说错、误改普通的话不算过度纠正、按次数估算）；参数和规则是看着全班录音挑的；有哪些没做到的。

## 十、常见坑

1. **忘了加 `--hotword on`**：热词纠错默认是关的，基线什么都不纠，g5（保留了开关的话）也什么都不做，对比表的差值全是 0。除了专门测"关"的那一次，命令里都要写 `--hotword on`。
2. **在 `config.yaml` 里改 `min_len`、`max_syllable_mismatch`**：基线也读这两个参数，改了以后基线跟着变，`compare.py` 比出来还是 0。参数写在本组文件里（6.0 的 `MIN_LEN`、`MAX_MISMATCH`）。真改过 `config.yaml` 的，马上改回来。
3. **只看专名正确率**：参数一松，专名正确率可能上去，可普通的话被乱改、故意说错的名字被"改对"。三个数（专名正确率、过度纠正、热词纠错次数）加上字错率一起看，再用 7.4 的小工具看例子。
4. **以为过度纠正是 0 就没问题**：指标只数变体表里有的说法，误改普通的话也不算过度纠正，而且次数是估算的（第五节 5.6 的盲点）。即兴说错、变体表里没有的名字被改对，"团队里"被改成"团队价"，都数不到，要靠纠错例子表。
5. **把变体表抄进代码**：把"松风行舟""听松坊"放进保护名单，过度纠正马上变成 0，但这是看着答案答题，什么也说明不了。保护名单只放被误改的**普通的话**。
6. **只改了 `text`，没改 `text_raw`**：网页上看着改对了，测评一点没变，因为专名正确率和字错率用的是 `text_raw`。两个字段都要改。
7. **直接改了传进来的段落**：比如写 `segments[0]["text"] = ...`，没有先 `seg = dict(seg)`。会悄悄影响后面的步骤和测评。先复制一份再改。
8. **在网页热词框里加了词，测评没变化**：测评命令用的是 `data/hotwords.txt`，不读网页上的热词框。想多用一些词，写在本组文件里。
9. **改了 `data/hotwords.txt` 或 `data/hotword_variants.csv`**：这两张表是测评的标准，也不是本组文件，不能改。觉得有错有漏，告诉老师。
10. **两个字的热词直接放开**：`MIN_LEN` 改成 2，"桌子"会变"镯子"、"饮食"会变"银饰"。要放开就加前后文条件（方向 3）。
11. **在网页上切到 g5，结果没变化**："热词纠错"开关要选**开**；改过代码要关掉黑色窗口、重新双击 `start.bat`。
12. **改了降噪、端点检测的做法或参数**：识别结果跟着变，要重新识别（很慢），而且和基线不是同一份识别结果，比出来的差值不全是热词带来的。本组测评时这几个槽位一律用基线。不要随便加 `--no-cache`。
13. **`--out` 用了同一个文件夹**：后一次的 `hotwords.md` 会盖掉前一次。每次用不同的子文件夹（`off`、`on`、`after`、`try_3_1`……）。
14. **提交后自动测试有一项变红**：`tests/test_groups.py` 里有一项检查"各组初始做法和基线一样"（`test_text_stubs_equal_baseline`），它会拿"我们报的是雾影行走旅行社，团费两千八百块"这句话、在热词纠错打开时比较 `g5` 和基线。你们的改动改变了这句话的结果，这一项就会失败，这是预料之中的。**不要去改这个测试文件**（不是本组文件），在 PR 说明或代交的 `说明.txt` 里写清楚，由老师处理。其他红叉要自己查原因；自动测试还会做代码检查，没用到的 `import` 没删也会报错。
15. **在文件开头导入大的库**：本组文件只需要 `re`、`collections` 和 `pipeline` 里的小函数；方向 4 的 `sherpa_onnx` 只能在实验函数里面导入。
16. **文件保存成了别的编码**：用记事本保存时编码选 UTF-8，否则中文注释、保护名单里的汉字可能变成乱码，甚至运行报错。
17. **抽查时替别组点了"保存参考文本"**：保存一次就会被记成一次校对，验收表的"校对遍数"就不准了。别组的问题只记录、交给他们改。
18. **把参考文本"改规范"**：人说错的名字不能改成正确名称；识别结果里的同音别字不能抄进参考文本。参考文本只跟着录音里人实际说的话走，绝对不能改成识别结果。
19. **录音时把名称念得特别慢、特别清楚，或者把故意说错的地方说对了**：测出来的结果就不真实了，过度纠正也测不到。照剧本、像平常说话一样演。
20. **把导出的核查初稿和识别结果放进 `reports\g5\`**：导出的 ZIP 里有片段音频，Word、CSV 和小工具的输出里有同学录音的文字。它们只留在本机工作文件夹，不提交；`reports\g5\` 里只放统计表和报告。
21. **用云端热词、在线识别**：不能把录音上传到在线转文字网站，也不能用云端识别服务的热词功能；不能把录音、录音转出来的文字粘贴给 AI 工具，只能给 AI 看代码、报错和测评数字表格。
22. **即兴时说了真实的旅行社名、店名**：剧本里的名称都是虚构的。说漏了真实名称就从头重录，并告诉老师。
23. **机房电脑还原，东西没了**：每次下课前按"下课前拷走什么"拷到 U 盘。
