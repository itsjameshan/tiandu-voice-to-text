## 一、你们组负责什么

**一句话**：让流水线第 5 步把口语里的数字写规范（"两千八百块"→"2800元"、"零八七一 零零零零 六六八八"→"0871-0000-6688"），并把金额、电话、证号、时刻等**提取得更全、更准**，再用"分类型的提取正确率"说明有没有变好（没变好也如实写）。

- **对应步骤**：⑤ 数字规范化，基线代码在 `pipeline/step5_normalize.py`。
- **槽位**：`normalize`（数字规范化）。这一步给每个段落补两样东西：
  - `numbers`：文字里提到的数字的规范写法，如 `2800元`、`15:40`、`0871-0000-6688`、`YN-0000-3721`；
  - `entities`：文字里提到的旅行社、店铺等名称，如"拾光滇程旅行社"（这一项不算你们的主要指标，可以不改）。
- **为什么重要**：核查初稿里"提取出来的金额、电话、证号"就来自这一步。工作人员核对"导游收了多少钱、旅行社电话是多少"时会先看这里，所以提取错了、漏了都要尽量少；但不管多准，都**必须人工对照原声复核**。
- **你们的产出**：在 `pipeline/groups/g4_numbers.py` 里写出 `g4` 做法，测出"**基础结果 + 改进后结果 + 对比数据**"，写成报告并答辩。
- **主要指标**：按类型分开的**正确率**（提取出来的里面有多少是对的）和**召回率**（标准答案里有多少被提取出来了）。
  - 主指标：金额、电话、证号、合同号、订单号、时刻、日期（和纠纷核查直接相关）；
  - 次要指标：数量、时长、其他。
  - 在两个地方测：**剧本文字**（工具自动测，不需要录音）和**本组录音**（手工抽测，安静 Q、嘈杂教室 N、口袋/远距离 F 三种条件分开）。
- **数据阶段（第 1—6 周）另外分管一件事**：抽查全班 72 份参考文本里数字、金额、电话、证号的读法是否和录音一致（第 5 周开始抽查，第 6 周继续抽查并汇总问题）。

## 五、基线做法是怎么工作的

### 5.1 第 5 步在流水线里的位置，和两种模式

```
第 3 步识别出的文字 ──▶ 第 4 步分出说话人 ──▶ 第 5 步 数字规范化（normalize）  ← 第 4 组的槽位
                                               │  补上 numbers（规范写法）和 entities（名称）
                                               ▼
                                      第 6 步话术分类 ──▶ 第 7 步疑似片段 ──▶ 第 8 步核查初稿
```

同一个函数会在两种模式下被调用（`mode` 参数）：

| 模式 | 什么时候用 | 输入的文字长什么样 | 第 5 步做什么 |
|---|---|---|---|
| `spoken`（汉字读法） | 网页"剧本文本演示"页；测评模式；`evaluate.py numbers` 在剧本文字上测 | "这个手镯两千八百块" | 先把原文存进 `text_raw`，再把汉字读法转成阿拉伯数字，然后提取 |
| `display`（显示模式） | 网页"整理录音"页（平时处理录音） | "这个手镯2800块"（识别时已经做了逆文本规范化，文字里已经是阿拉伯数字） | 只做提取，不改文字 |

记住这张表，后面很多"为什么网页上看不出变化"的问题都和它有关（见第十节第 7 条）。

另外两点：
- **字错率不受你们影响**：算字错率用的是汉字读法的识别结果（`text_raw`），所以你们改第 5 步不会改变字错率。
- **话术分类基本不受你们影响**：按设计，分类前另有一套只用标准库的文字归一（`pipeline/text_norm.py`，数字串统一换成 `#`），你们改第 5 步不会悄悄改变分类器的输入。

### 5.2 汉字读法 → 阿拉伯数字（`spoken_to_digits`，按顺序做五件事）

1. **逐位读的号码**：前面带两个大写字母的证号、合同号、订单号（"YN 零零零零 三七二一"→`YN-0000-3721`，"HT 二零二六 四个零 幺幺八"→`HT-20260000-118`），以及**用空格隔开**的号码段（"零八七一 零零零零 六六八八"→`0871-0000-6688`）。这一步必须最先做，因为后面的 cn2an 会把"零八七一"当成一个数，变成"871"，开头的 0 就丢了。
2. **时刻**：只有前面紧挨着"上午、下午、早上、晚上、中午"的"X点""X点Y""X点半"……才转（"下午三点四十"→`下午15:40`；下午、晚上加 12）。另外"X点钟"也转。没有这些时间词的"九点五十"**不转**——不知道是上午还是下午，也怕把"便宜一点"的"一点"当成时刻。
3. **保护词**：热词表里的名称和 `PROTECTED_WORDS` 里的词（"一下""一般""一点"……）先换成占位符，转完再换回来，否则会变成"1下""1般"。量词前面的"两"先改成"2"（cn2an 会漏掉"两盒"）。
4. **cn2an 转换**：其余的汉字数字交给 cn2an 库转（"两千八百"→`2800`）。cn2an 是一个中文数字和阿拉伯数字互相转换的小库。
5. **块→元**：紧跟在数字后面的"块""块钱"改成"元"（`2800块`→`2800元`）。

### 5.3 提取（`extract_numbers`）

一组正则表达式**按优先级依次找**：合同号 → 证号/订单号 → 电话 → 时刻 → 日期 → 金额 → "第几" → 时长 → 数量 → 公共热线（12301 等）→ 不带单位的数。每认出一个，就把那一段"涂掉"，免得被后面的规则重复认；最后按出现顺序去重。

最后一条规则要特别注意：**剩下的、不带任何单位的两位以上的数，一律当成金额**（口语里说价钱常常不说"块"，如"二百八一位"）。这条规则会把房间号、足银"九九九"、电话尾号"六六八八"也当成钱——这就是你们的改进方向之一。

### 5.4 类型（`number_type`）：测评时按类型分开统计

给一个规范写法判断类型，按下面的顺序，先符合哪条就是哪类：

| 顺序 | 条件 | 类型 | 例子 | 主/次 |
|---|---|---|---|---|
| ① | 含"元" | 金额 | `2800元`、`151.2元`、`30-40元/盒`、`38元/克` | 主 |
| ② | 形如 3～4 位-4 位-4 位 | 电话 | `0871-0000-6688` | 主 |
| ③ | 以 `HT-` 开头 | 合同号 | `HT-20260000-118` | 主 |
| ④ | 以 `DD-` 开头 | 订单号 | `DD-0000-5566` | 主 |
| ⑤ | 两个大写字母-4 位-4 位 | 证号 | `YN-0000-3721` | 主 |
| ⑥ | 形如 `15:40`（小时前面不补 0） | 时刻 | `19:20`、`8:30` | 主 |
| ⑦ | 年、月、日的写法（年份必须是 4 位数字，所以"5日游""7个工作日"都不算） | 日期 | `2026年10月18日`、`10月15日`、`15日` | 主 |
| ⑧ | 以分钟、小时、天、晚、年、个月、个工作日等结尾 | 时长 | `70分钟`、`2.5小时`、`7个工作日` | 次 |
| ⑨ | 以量词结尾，或以"第"开头 | 数量 | `3人`、`5张`、`806房间`、`第2页`、`10%`、`9折` | 次 |
| ⑩ | 其余 | 其他 | `12301`、`999`、`1218`、`6688` | 次 |

**格式差一个字，类型就可能变**：`1218元` 是金额，`1218` 是其他，`1218房间` 是数量。

### 5.5 测评怎么比（`numbers_accuracy`）

拿 `data/lines.csv` 每一行的 `numbers` 当标准答案，和工具从这一行提取出的结果比较（同一行里去重后当集合比，**一字不差才算对上**）。每种类型数三个数：

- **标准答案数**（gold，测评输出里叫"金标准个数"）：标准答案里有几个；
- **提取数**（pred，"提取个数"）：工具提取出几个；
- **对上数**（hit，"命中个数"）：两边都有的有几个。

**正确率 = 对上 ÷ 提取；召回率 = 对上 ÷ 标准答案。**

举例：G4-S1 里游客乙说"那五百四你原路转回来就行，我们住幺二幺八"，标准答案是 `540元`、`1218`。基线提取出 `540元`、`1218元`。于是：
- 金额：标准答案 1 个，提取 2 个，对上 1 个（`540元`）——多出来的 `1218元` 拉低了金额的**正确率**；
- 其他：标准答案 1 个（`1218`），提取 0 个，对上 0 个——拉低了"其他"的**召回率**。

所以两个数都要看：只看召回率，"什么都当成金额"也能很高；只看正确率，"什么都不提取"也不会错。

## 六、改进方向（由易到难）

先选 1—2 个方向做，做透比做多重要。方向的编号和 `g4_numbers.py` 开头说明里的一致；README 第 8 周写的"两个半小时""三四十块"、逐位读号码，就是方向 2 和方向 3。不管哪个方向，最后都要用正确率、召回率说话；**测出来没有变好也是有效结果**，如实写进报告。下面代码里的写法**只是举例，不代表会更好**。

**一条总原则：规则要按"一类说法"写，不要按"某一句台词"写。** 比如写 `if "七点二十" in text` 然后直接返回 `19:20`，在剧本上会"变好"，但这是看着答案定规则，换一段录音就没用了，答辩时也讲不过去。

### 6.0 先搭好架子（所有方向都用这个写法）

思路：**先改文字 → 交给基线 → 再改结果**。把 `normalize_g4` 改成下面这样，两个小函数现在什么都不改，所以结果应该和基线完全一样（先跑一次测评确认，见第七节）：

```python
from pipeline.methods import register
from pipeline.step5_normalize import normalize_baseline


def fix_spoken(text: str) -> str:
    """第 4 组：汉字读法的文字，交给基线之前，先改写基线处理不好的说法。现在什么都不改。"""
    return text


def fix_numbers(numbers: list[str], text_raw: str) -> list[str]:
    """第 4 组：基线提取完以后，再修正提取结果（比如去掉认错的金额）。现在什么都不改。"""
    return numbers


@register("normalize", "g4")
def normalize_g4(segment: dict, mode: str, cfg: dict) -> dict:
    """第 4 组的规范化做法。mode 是 "spoken"（汉字读法）或 "display"（识别已转好数字）。"""
    segment = dict(segment)                                  # 复制一份，不改传进来的段落
    if mode == "spoken":
        if not segment.get("text_raw"):
            segment["text_raw"] = segment.get("text", "")    # 和基线一样：原文先存进 text_raw
        segment["text"] = fix_spoken(segment.get("text", ""))
    result = normalize_baseline(segment, mode, cfg)          # 剩下的交给基线
    raw = result.get("text_raw") or result.get("text", "")   # 显示模式下可能没有汉字原文
    result["numbers"] = fix_numbers(result["numbers"], raw)
    return result
```

注意：
- `fix_spoken` 只在 `spoken` 模式起作用；`fix_numbers` 两种模式都起作用。
- 基线看到 `text_raw` 已经有了，就不会再覆盖，所以 `text_raw` 里保留的是**没改过的原文**。
- 用到正则时，在文件开头加 `import re`；没用到的 `import` 要删掉（自动测试会检查）。

### 方向 1：没有时间词的时刻（提升空间最大）

**问题**：剧本里大多数时刻前面都没有"上午、下午"，如"七点二十在大堂集合""九点十分结束""四点半出发""三点五十准时开车"，基线一律不转。

**第一步（容易）：补时间词**。基线只认"上午、下午、早上、晚上、中午"，可以在 `fix_spoken` 里先处理"今晚""傍晚""明早"这类词。基线里有一个现成的小函数 `_time_text`（给它时间词、小时、分钟，拼出 `20:00`），可以借来用：

```python
import re

from pipeline.step5_normalize import _time_text   # 基线里拼"15:40"的小函数

# 第 4 组：基线不认识的时间词，当成哪个基线认识的时间词来算（举例）
MORE_TIME_WORDS = {"今晚": "晚上", "傍晚": "晚上", "明早": "早上"}
_MORE_TIME = re.compile(r"(今晚|傍晚|明早)([一二两三四五六七八九十]{1,3})点(半|整|钟|[一二三四五]?十[一二三四五六七八九]?)?")


def fix_time_words(text: str) -> str:
    """"今晚八点" → "今晚20:00"。认不出就原样留着。"""
    def change(m):
        result = _time_text(MORE_TIME_WORDS[m.group(1)], m.group(2), m.group(3) or "")
        return m.group(0) if result is None else m.group(1) + result
    return _MORE_TIME.sub(change, text)
```

然后在 `fix_spoken` 里写 `text = fix_time_words(text)`。

**第二步（难）：完全没有时间词的**。思路：
1. 找"X点Y"：Y 必须是"半""整"或分钟数（"二十""五十""十分"），这样"便宜一点"不会被认成时刻；后面紧跟数字或"多"的不转（"两点五"是小数，"八点多"说不准几分）。
2. 判断上午还是下午：同一句里有"晚""今晚""晚饭""演出"之类的词就加 12；有"早上""上午""明天早上"就不加；都没有时，旅游行程里"一点到六点"多半是下午……这些规则都由你们自己定，**一定会有判断错的时候**，要统计出来。
3. "差十分八点"：先算出"八点差十分"= 7:50，再判断上午下午。
4. 改口省掉的时间词：G1-S3 里"我是晚上八点二十的，不对，八点五十"，标准答案是 `20:20`、`20:50`——同一句里前面出现过的时间词，后面可以接着用。

**为什么一定会错**：G1-S1 里"现在是九点五十"是上午（标准答案 `9:50`），G4-S1 里"九点十分结束"是晚上（`21:10`）。同样是"九点"，只能靠上下文；而录音上一个段落有多长由第 2 步切出来，不一定和一句台词一样，能用的上下文更少。

### 方向 2："两个半小时""半个小时""三四十块"这类说法

**问题**：cn2an 把"两个半小时"转成"2个0.5小时"，"半个小时"转成"0.5个小时"；"三四十块""八九百"这种约数它转不了。

**标准答案的写法**（从 `data/lines.csv` 里查到的，你们的结果要和它一字不差）：

| 说法 | 标准写法 |
|---|---|
| 两个半小时、四个半小时 | `2.5小时`、`4.5小时` |
| 半个小时 | `30分钟` |
| 一刻钟 | `15分钟` |
| 三四十块一盒 | `30-40元/盒` |
| 八九百 | `800-900元` |
| 两三万 | `2-3万元` |

**怎么做（固定说法，最容易上手）**：在 `fix_spoken` 里先把它们换成基线认识的写法：

```python
import re

# 第 4 组：基线处理不好的固定说法，先换成基线认识的说法（举例）
FIXED_PHRASES = {
    "半个小时": "三十分钟",
    "一刻钟": "十五分钟",
}
# "两个半小时""四个半小时" → "2.5小时""4.5小时"
_HALF_HOURS = re.compile(r"([一二两三四五六七八九])个半小时")
_ONE_DIGIT = {"一": "1", "二": "2", "两": "2", "三": "3", "四": "4",
              "五": "5", "六": "6", "七": "7", "八": "8", "九": "9"}


def fix_spoken(text: str) -> str:
    """第 4 组：汉字读法的文字，交给基线之前，先改写基线处理不好的说法。"""
    for old, new in FIXED_PHRASES.items():
        text = text.replace(old, new)
    text = _HALF_HOURS.sub(lambda m: _ONE_DIGIT[m.group(1)] + ".5小时", text)
    return text
```

**约数（难一点）**：思路是找"相邻的两个数字 + 十/百/千/万"（"三四十""八九百""两三万"），检查后一个数正好比前一个大 1，换成"30-40"这样的写法；再把"块一盒"变成"元/盒"。小心别误伤号码：逐位读的号码（"一二三零一"）后面不会紧跟"十、百、千"。改完用第七节 7.6 的办法拿几句话试一试。

### 方向 3：没有空格的逐位读号码

**问题**：基线只认**用空格隔开**的号码段。可是测评模式的识别结果没有空格、没有标点，"零八七一零零零零六六八八"会被 cn2an 当成一个大数，变成 `87100006688元`——开头的 0 丢了，还被当成了钱。另外"零八七幺，四个零，然后是两个六两个八"这种口语读法，基线也认不出。

**思路**（要放在 `fix_spoken` 里，因为必须在 cn2an 之前做）：
1. 找连续 7 个以上、全部由"零〇一二三四五六七八九幺"组成的字（中间没有"十、百、千、万"）——这很可能是电话或编号；
2. 逐个字换成数字："幺"是 1；
3. 按长度和开头判断：11—12 位、以 0 开头的，按"区号-4 位-4 位"写成 `0871-0000-6688`；前面紧挨着两个大写字母的（YN、DD），按证号、订单号写；
4. 直接写成阿拉伯数字的规范写法，这样 cn2an 不会再动它，基线的电话规则也能认出来；
5. 进阶："两个六两个八""四个零"这种"几个几"的读法，先展开成"六六八八""零零零零"，但只在号码旁边展开，别把"两个人"也展开了。

**提醒**：剧本里的号码全是虚构的。测试时只用剧本里的号码或自己编的、明显是假的号码（比如中间带"零零零零"），不要写进任何真实的电话号码。

### 方向 4：不是金额的数不要当成钱

**问题**：基线最后一条规则把不带单位的两位以上的数都当成金额。足银"九九九"、房号"三零六"、"幺二幺八"、电话尾号"六六八八"都被当成了钱。

**提示**：逐位读的数（"幺二幺八"，中间没有"十、百、千"）多半是编号，不是价钱。可以在 `fix_numbers` 里检查：这个数在原文里是不是逐位读的？是，就去掉"元"：

```python
# 阿拉伯数字 → 逐位读时的汉字
_TO_CHINESE = {"0": "零", "1": "一", "2": "二", "3": "三", "4": "四",
               "5": "五", "6": "六", "7": "七", "8": "八", "9": "九"}


def fix_numbers(numbers: list[str], text_raw: str) -> list[str]:
    """第 4 组：逐位读出来的数（如"幺二幺八"）多半是房号、编号，不是钱，去掉"元"。"""
    raw = text_raw.replace("幺", "一").replace("〇", "零")   # 统一写法，方便比较
    fixed = []
    for value in numbers:
        digits = value[:-1] if value.endswith("元") else ""   # "1218元" → "1218"
        read_one_by_one = "".join(_TO_CHINESE[d] for d in digits) if digits.isdigit() else ""
        if len(digits) >= 3 and read_one_by_one and read_one_by_one in raw:
            value = digits                                      # 原文里是逐位读的：不当成金额
        if value not in fixed:                                  # 去重，保持原来的顺序
            fixed.append(value)
    return fixed
```

**要想清楚的地方**：
- 显示模式下（"整理录音"页）原文已经是阿拉伯数字，上面这个判断不起作用。录音上怎么判断"1218"是房号？可以看它前后有没有"住""房间""号"这类字。
- 更多例子：G2-S3 里"一克三十八"标准答案是 `38元/克`（单价），"一块银板"的"块"是量词，不是钱。

### 方向 5（选做）：其他已知问题

这些在 `step5_normalize.py` 开头的"可改进方向"里都列了：

- **带角、毛的金额**："一百五十一块二"→`151.2元`，"三十三块六"→`33.6元`，"四毛钱"→`0.4元`。注意"三十三块六一分不少"这句，基线会把"六一"连在一起转成"61"。
- **cn2an 转错的固定说法**："十分抱歉"变成"10分抱歉"，"一分没少"变成"1分没少"，还有"一口价""一段""对一对"。基线说明里说可以往保护词里加，但**不要改基线文件**。最简单的办法是在自己的函数里，基线转完以后把这些词**改回来**（只在 `spoken` 模式做）：

  ```python

  CHANGE_BACK = {"10分抱歉": "十分抱歉", "1分没少": "一分没少", "1口价": "一口价", "对1对": "对一对"}
  ```

  然后在 `normalize_g4` 里、`normalize_baseline` 之后加：`spoken` 模式下，对 `CHANGE_BACK` 里的每一对，用 `result["text"].replace(错的, 对的)` 改回来。
  这类改进主要让**文字**变对，数字提取的指标**不一定变**。报告里单独列一张"改对的句子"例子表。
- **保护了"一点"以后，小数"一点五"也不转了**：想一想怎么区分"便宜一点"和"一点五元"。

`evaluate.py numbers` 把结果写进 `--out` 指定的文件夹：`numbers.md`（汇总表）和 `numbers.csv`，命令行窗口里也会打印汇总。`compare.py` 写出 `compare_numbers.md` 和 `compare_numbers.csv`：每行一个分组项，列出基线、改进、差值。这张表直接放进报告的"对比数据"一节；报告开头会自动写明做法和参数。

看的时候：

1. **每种类型分开看**，主指标（金额、电话、证号、合同号、订单号、时刻、日期）和次要指标（数量、时长、其他）分开写。
2. **正确率和召回率一起看**，还要看后面的计数（标准答案数、提取数、对上数）。分母是 0 时比率记成 0.0，这时只看计数。
3. **常见的"跷跷板"**：方向 4 把"1218元"改成"1218"以后，金额的正确率会变，"其他"的召回率也会变——两边都要写。
4. **剧本文字上的结果偏乐观**：规则是你们看着这些剧本写的，等于"看着题目定规则"。所以还要在录音上抽测（7.4），并在报告的"局限"里写明。
5. 差值很小时，不要急着说"变好了"：到"剧本文本演示"页找出变化的句子，看看是真的改对了，还是碰巧。

### 7.4 在录音上抽测（手工统计）

`evaluate.py numbers` 只在剧本文字上测。README 要求你们"在剧本文字和录音上"都测，录音上用下面的手工办法。**建议本组 9 段录音都做**；时间不够时至少 Q、N、F 各 1 段，并在报告里写明做了哪几段。基线和 g4 必须用**同样的几段录音、同一份标准答案、同一个数据池版本**。

**先准备标准答案**（每段录音一张表，第 7 周做一次，第 8 周照用）：

3. 同一段录音里重复的值只留一个。
4. 每个值按第五节 5.4 的表写上类型。

**再跑工具、对答案**：
1. 把 `D:\data_pool\normalized\G4-S1-Q.wav` 复制一份到自己的工作文件夹，例如 `D:\asr\work\`（不要在数据池文件夹里做任何改动）。

## 十、常见坑

1. **改了 `config.yaml` 的 `normalize: g4`，忘了改回来**：之后"剧本文本演示"页、整理录音的默认做法都悄悄变成了 `g4`；基线测评如果没写 `--method normalize=baseline`，测的其实也是 `g4`，对比表差值就成了 0。看完马上改回，基线命令一定写明 `--method normalize=baseline`。
2. **直接改了传进来的段落**：比如写 `segment["text"] = ...` 却没有先 `segment = dict(segment)`。会悄悄影响后面的步骤和测评。先复制一份再改。
3. **把 `text_raw` 改坏了**：`text_raw` 要保留没改过的原文（汉字读法）。在 `spoken` 模式里先存原文、再改 `text`，顺序不能反。
4. **格式差一个字就不算对上**：`2.5个小时` 和 `2.5小时`、`08:30` 和 `8:30`（小时前面不补 0）、`15：40`（全角冒号）和 `15:40`、`151元2` 和 `151.2元`、`0871—0000—6688`（中文破折号）和 `0871-0000-6688`。一律以 `data/lines.csv` 的写法为准。
5. **只看召回率或只看正确率**：把所有"X点Y"都当成时刻，时刻的召回率会上去，正确率可能下来；两个都要报。
6. **看着答案写规则**：针对某一句台词写死结果，剧本上的数字会变好看，换一段录音就不行，答辩也讲不过去。规则要按"一类说法"写；剧本上的结果偏乐观，要写进局限。
7. **在"整理录音"页切到 g4，数字却没变化**：这一页是显示模式，识别时已经转成了阿拉伯数字，`fix_spoken` 不起作用。要看 `spoken` 模式的改动，用"剧本文本演示"页、`evaluate.py numbers` 或第七节 7.6 的命令。
8. **把识别错算成规范化错**：录音上数字对不上，先听原声、看文字。识别听错是第 3 步的问题，你们的改动救不回来，要分开统计。
9. **误伤正常的话**：改了规则以后，"便宜一点""两个人""一五一十""一二三零一"会不会被转坏？每次改完都拿这些句子试一下。
10. **为了正确率去改标准答案**：`data/lines.csv` 和冻结的参考文本都不能为了让结果好看而改。觉得标准答案有错，告诉老师。
11. **提交后自动测试有一项变红**：`tests/test_groups.py` 里有一项检查"各组初始做法和基线一样"（`test_text_stubs_equal_baseline`），它会拿"团费两千八百块"这样的一句话比较 `g4` 和基线。如果你们的改动改变了这句话的结果，这一项会失败，这是预料之中的。**不要去改这个测试文件**（不是本组文件），在 PR 说明或代交的 `说明.txt` 里写清楚，由老师处理。其他红叉要自己查原因；自动测试还会做代码检查，没用到的 `import` 没删也会报错。
12. **在文件开头导入大的库**：本组文件只需要 `re` 和基线里的函数；不要导入 sherpa-onnx、gradio、tensorflow。
13. **改了代码网页上没变化**：要关掉黑色窗口、重新双击 `start.bat`。
14. **文件保存成了别的编码**：用记事本保存时编码选 UTF-8，否则中文注释和规则里的汉字可能变成乱码，甚至运行报错。
15. **抽查时替别组点了"保存参考文本"**：保存一次就会被记成一次校对，验收表的"校对遍数"就不准了。别组的问题只记录、交给他们改。
16. **把参考文本"改规范"**：参考文本只跟着录音里人实际说的话走：不写阿拉伯数字；说"两百八"不能改成"二百八十"；说错的数照实写。绝对不能改成识别结果。
17. **把导出的核查初稿放进 `reports\g4\`**：导出的 ZIP 里有片段音频，Word、CSV 里有同学录音的文字。它们只留在本机工作文件夹，不提交；`reports\g4\` 里只放统计表。
18. **即兴时说了真实号码**：剧本里的号码都是虚构的。说漏了真实电话、证号就从头重录，并告诉老师；写测试、试命令时也只用剧本里的号码。
19. **`--out` 用了同一个文件夹**：后一次的结果会盖掉前一次。每次用不同的子文件夹。
20. **机房电脑还原，东西没了**：每次下课前按"下课前拷走什么"拷到 U 盘。
21. **把录音交给在线工具或 AI**：不能把录音上传到在线转文字网站，也不能粘贴给 AI 工具；只能给 AI 看代码、报错和测评数字表格。
