# 各组以"做法"接入，基线做法永久保留

每组的改进不直接改基线代码，而是写在本组自己的文件（`pipeline/groups/gN_*.py`）里，登记成某个槽位的一个做法，用配置或界面切换。这样基线一直在，测评工具能在同一份数据上一键对比"基线 vs 改进"，正好产出课程要求的"基础结果 + 改进后结果 + 对比数据"；8 个组改不同的文件，提交时不冲突，老师审核只看一个文件，组长登不上 GitHub 时老师也能直接收文件代交。

## 考虑过的做法

- 各组直接改基线文件（build_spec 原来的写法）：最简单，但基线会被覆盖，对比要靠 git 历史，第 6、7 组同改一个文件会冲突。
- 各组完全独立开发、第 9 周老师手工串联：隔离最好，但接口容易走样，串联那一周风险最高。
