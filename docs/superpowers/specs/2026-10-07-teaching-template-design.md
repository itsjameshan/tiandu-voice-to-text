## 1. 问题陈述

老师要带 31 名专科生（学过 Python，没学过深度学习，大多数没用过 GitHub）用 10 周做一个语音识别项目：把游客提交的投诉录音整理成供人工复核的"核查初稿"。目前只有设计资料（交接文档、24 个虚构剧本、开发规格、项目介绍视频），没有代码，没有学生能照着做的周计划和任务书，也没有采集和清理语音数据的具体方法。

现实约束：

1. 机房是 Windows 电脑，**第 1 周没有网络**，重启后**大概率会还原**，但已装有 TensorFlow 和一些常用 Python 包；
2. 学生不知道 GitHub 是什么，可能登录不上；
3. 项目用现成的预训练识别模型，学生录的音主要用来**测评**，所以**数据质量决定后面所有测量是否可信**——老师希望把时间重点放在采集和清理数据上，原理和 TensorFlow 小实验压缩；
4. 最后每组要做出自己那一步的改进，整个项目要能交给别人用。

## 2. 解决方案

在本仓库里交付一套"教师模板 + 课程材料"：

1. **能运行的完整基线**：按 build_spec 做好八步处理流程、Gradio 网页界面、测评工具，全部有测试；每一步都有一个简单可用的"基线做法"，各组在基线上加自己的"改进做法"。
2. **Windows 免安装便携包**：解压即用，双击启动，不联网、不要管理员权限；由 GitHub 在真实的 Windows 电脑上自动打包并测试，老师下载一次拷进 U 盘。
3. **以数据为重点的 10 周课程**：数据工作约 4 周，有验收标准和工具支持；原理压缩成 1 周，并直接用于检查录音质量。
4. **中文 README 首页 + 8 份组任务书**：写清楚 31 人怎么分工、每组每周做什么、怎么做、交什么、怎么验收。
5. **数据配套**：录音规范、同意书模板、入池质检、参考文本校对助手、标注方法、数据池验收表、约 1000 句话术分类补充句子（由 AI 生成、只有文字、标明来源）。
6. **软件工程配套**：前 6 周学生不碰 GitHub；第 7 周起只有 8 个组长用 GitHub Desktop 提交，老师审核合并；登不上时老师代交。每次提交自动在 Windows 和 Linux 上跑测试。

### 5.2 流水线与"做法"登记

**对外接口（最高的测试接缝）**：`run_pipeline(path, options=None, progress=None) -> (segments, meta)`，按顺序执行八步，返回统一中间格式的段落列表和元信息。界面、测评工具、便携包自检都只调用它或各步的公开函数。

**做法登记（各组接入的接缝）**：每个可替换的环节叫一个"槽位"，每个槽位登记若干"做法"。基线做法叫 `baseline`，永远保留；各组做法叫 `g1`、`g2`……用哪个由 `config.yaml` 的 `methods` 或界面"高级设置"决定。

| 槽位 | 所在步骤 | 函数签名（输入 → 输出） | 基线做法 | 负责组 |
|---|---|---|---|---|
| `denoise` | 2 | (采样数组, 采样率, 配置) → 采样数组 | 原样返回 | 第 1 组 |
| `vad` | 2 | (采样数组, 采样率, 配置) → [(开始, 结束)] | Silero VAD | 第 1、2 组 |
| `enhance` | 2 | (采样数组, 采样率, 配置) → 采样数组 | 原样返回（给远距离/口袋录音用，如增益、均衡） | 第 2 组 |
| `hotword` | 3 | (段落列表, 热词表, 配置) → 段落列表 | 拼音相似度纠错（默认关闭） | 第 5 组 |
| `diarize` | 4 | (采样数组, 采样率, 段落列表, 配置) → 段落列表（填 speaker_id） | pyannote 分割 + CAM++ + 聚类 + 按重叠配说话人 | 第 3 组 |
| `normalize` | 5 | (段落, 模式, 配置) → 段落（填 text、numbers、entities） | 正则 + cn2an + 逐位读数规则 | 第 4 组 |
| `classify` | 6 | (文字列表, 配置) → 7 类之一的列表 | 关键词规则；有训练好的模型且装了 TensorFlow 时可选模型 | 第 6、7 组 |
| `clips` | 7 | (段落列表, 采样数组, 采样率, 配置) → [(开始, 结束, 段落序号)] | 有标签的段前后各留 1 秒 | 第 8 组 |

每个组文件（如 `pipeline/groups/g1_denoise.py`）一开始就登记好一个能运行的做法，内容是调用基线，并用中文写清楚"在这里改什么、怎么测、注意什么"。所以第 1 天全流程就能跑通，各组只需把自己文件里的函数体换成改进做法。

步骤 1（入池与格式统一）和步骤 8（核查初稿）是教师模板，不开放替换。

**模型只加载一次**（模块级缓存）；识别分批解码并更新进度；每一步打印耗时和实时率。

`pipeline/__init__.py` 和 `pipeline/text_norm.py` 在导入时不加载 sherpa-onnx 等重依赖，所以第 6、7 组可以用机房自带的 Python（只装了 TensorFlow 和 numpy）运行 `tools/train_classifier.py`。

### 5.3 统一中间格式

完全沿用 build_spec 第 3 节：五个固定字段（开始时间、结束时间、说话人、文字内容、标签）和可选字段，中文表头和顺序固定，CSV 用 UTF-8 带 BOM，JSON 带 `meta.notice`。不做任何改动。

### 5.4 界面（Gradio）

在 build_spec 第 7 节的基础上：

- 标签页"整理录音"：同 build_spec，另加折叠的"高级设置"，每个槽位一个下拉框，列出已登记的做法。
- 标签页"剧本文本演示"：同 build_spec。
- **新增标签页"数据校对"**：从数据池选一个录音，工具用测评模式识别（结果缓存），把识别结果和参考文本逐字对齐，列出每一段的时间、识别结果、参考文本对应部分，并标出不一致的地方；点一行播放这一段；下方可以直接修改参考文本并保存，保存时记下校对人和时间。只在本地数据池上用。
- **新增标签页"录音质检"**：上传或从数据池选一个录音，显示波形、语谱图、质检结果（时长、音量、削波、长静音、原始采样率），并用中文解释每项是什么意思、不合格怎么办。
- 标签页"使用说明"。
- 设置：`server_name="0.0.0.0"`、端口 7860、永远不设 `share=True`、`GRADIO_ANALYTICS_ENABLED=False`、上传大小限制、单任务队列、临时文件放在项目内的 `tmp/`（避开 Windows 中文用户名路径）、启动时自动打开浏览器（便携包）、设置了 `DEMO_USERNAME`/`DEMO_PASSWORD` 才要求登录。

### 5.5 数据配套（课程重点）

**数据池**（放在老师电脑或 U 盘；路径在 `config.yaml` 里可改，支持共享文件夹路径）：

```
data_pool/
  raw/                  学生交来的原始录音（入池后设为只读）
  normalized/           16kHz 单声道 16 位 WAV
  references/           每个录音一份参考文本，如 G1-S1-Q.txt（从剧本生成，再按实际录音校对）
  annotations/speakers/ 说话人时间标注，如 G3-S1-Q.csv（start, end, speaker）
  annotations/clips/    疑似片段起止标注
  digits/               选做：中文数字录音
  manifest.csv          清单（文件编号、剧本、条件、原始文件、转换后文件、时长、原始采样率、质检、上传时间、SHA-256）
  qc_report.csv         质检报告
  proofread_log.csv     校对记录（文件、校对人、时间、第几遍）
  acceptance.csv        验收表（每个计划录音一行：已交、命名、质检、校对遍数、说话人标注、片段标注、是否通过）
  versions/v1/          冻结的版本：清单、参考文本、标注的副本和校验值
```

**参考文本按录音逐条生成**：同一个剧本的 Q、N、F 三次录音，实际说的话会有出入（即兴、改口、打断），所以 `tools/export_references.py` 为 72 个录音各生成一份初稿（内容先照抄剧本台词），学生对照录音改成"实际说了什么"。计算字错率时用这份校对后的文本。

**数据流转**：手机 → 数据线 → 机房电脑 → U 盘或共享文件夹 → 老师电脑上的 `data_pool/raw/`。全程不上网。

**流程与验收标准**：

1. 试录（第 2 周）：每组录 1 个剧本（安静条件），走完入池、质检、识别，校准语速、手机设置和质检阈值；
2. 正式录音（第 4、5 周）：72 段，录前签同意书；
3. 入池：`tools/ingest_pool.py` 检查文件名（`G1-S1-Q.wav` 格式，不符合就报错、不猜）、统一格式、算 SHA-256、质检（只报告、不修改）；
4. 复录：质检不合格的按提示重录；
5. 校对参考文本：每个录音两个人各校对一遍（用"数据校对"标签页），记录进 `proofread_log.csv`；
6. 标注：每组至少 10 分钟说话人时间标注（用 Audacity 标签轨，`tools/labels_to_csv.py` 转成表格）；第 8 组定疑似片段起止的标注方法，各组标注自己的录音；
7. 验收：`tools/check_pool.py` 生成验收表，老师确认后 `tools/freeze_pool.py --version v1` 冻结。之后所有测评报告都写明用的是哪个版本。

**数据阶段各组分管一项数据质量**（和后面的专项对应，提前熟悉自己的方向）：

| 组 | 数据阶段负责 |
|---|---|
| 第 1 组 | 组织嘈杂教室（N）条件录音；用试录数据试定质检阈值（音量、静音） |
| 第 2 组 | 制定并执行口袋/远距离（F）条件录音规范（手机位置、距离记录） |
| 第 3 组 | 制定说话人时间标注规范，培训各组，抽查标注 |
| 第 4 组 | 抽查所有参考文本里数字、金额、电话、证号的读法是否和录音一致 |
| 第 5 组 | 抽查所有参考文本里虚构名称、行话的写法，记录实际说错或简称的地方 |
| 第 6、7 组 | 审核 AI 生成的分类补充句子（各审一半），抽查剧本台词的类别标注 |
| 第 8 组 | 制定疑似片段起止时间的标注规范，抽查 |

**话术分类补充句子**（`data/classification_extra.csv`）：由 Claude 生成约 1000 句，只有文字，7 个类别都有，重点补"威胁消费""服务态度""行程变更"和"正常讲解"（正常讲解多，才能压低误报）。规则与剧本写作规范相同（虚构名称、只写商业纠纷、措辞温和、不碰政治民族宗教、数字多用汉字读法）。每句标 `source=AI生成`、`reviewed=未审核`；第 6、7 组在第 5—6 周审核。`tools/check_classification_data.py` 检查类别是否合法、是否重复（含与剧本台词重复）、是否含红线词。**测评时测试集只用人写的剧本台词**（按组留一），补充句子只进训练集，并在报告中写明"用了 / 没用补充句子"两种结果。

**选做：中文数字录音**（`tools/tf_lab/`）：每人按顺序念"零到九"5 遍，停顿约 1 秒；`split_digits.py` 用 Silero VAD 切成 50 段并按顺序标注，段数不对时提示重录；`train_digits.py` 训练小型 CNN（MFCC 输入），按人留出测试。只在本地处理。

### 5.6 测评与对比

`tools/evaluate.py` 的子命令（口径同 build_spec 第 8 节）：

| 子命令 | 指标 | 需要的标注 |
|---|---|---|
| `cer` | 字错率（拆成错字、漏字、多字），按文件、录音条件（Q/N/F）、组汇总 | 校对后的参考文本 |
| `hotwords` | 专名正确率、过度纠正次数 | 参考文本 + `data/hotwords.txt`、`hotword_variants.csv` |
| `numbers` | 数字提取正确率、召回率，按类型（金额、电话、证号、合同号、订单号、时刻、日期 / 数量、时长、其他）分开 | 剧本 `numbers` 字段 |
| `speakers` | 说话人标错的时长比例（按最优对应） | 说话人时间标注 |
| `classify` | 各类准确率、召回率、混淆矩阵、误报率；按组留一（主结果）与随机划分（对照） | 剧本 `label` 字段 |
| `clips` | 片段起止误差、误报率 | 片段起止标注、剧本 `label` |

`tools/compare.py --slot denoise --method g1 --metric cer`：同一份冻结数据，分别用基线和某组做法跑一遍，输出 `reports/g1/compare_cer.md` 和 CSV（基线、改进、差值，按录音条件分开），报告开头自动写明数据版本、做法、参数、时间和局限说明。各组报告模板在 `reports/gN/README.md`：基线结果、改进做法、改进后结果、对比表、结论与局限。

在云端开发环境里没有学生录音，只用模型自带测试音频改名检验批量流程能跑通，**不报告任何字错率数字**。

### 5.7 Windows 运行

**便携包（主线）**：

- 内容：Python 3.11 嵌入版、全部依赖（不含 TensorFlow）、必需模型、ffmpeg（来自 `imageio-ffmpeg` 包）、项目代码和文档（不含 `handoff/`），以及 `启动.bat`、`自检.bat`。解压后约 600 MB，压缩包约 400 MB。
- 构建：GitHub Actions 在 `windows-latest` 上构建，构建后在同一台 Windows 机器上运行 `tools/selfcheck.py`（处理测试音频、检查输出）并启动服务自测，通过后上传为构建产物；打 `v*` 标签时附到 Release。老师在有网的电脑下载一次。
- 使用：解压到**纯英文路径**（如 `D:\asr\tiandu` 或 U 盘 `E:\asr\tiandu`），双击 `启动.bat`，浏览器自动打开。程序启动时检查路径是否含中文，含中文就提示移动位置。
- 机房会还原：便携包放在不还原的盘或 U 盘；数据池在老师电脑或 U 盘；每次下课前把自己的录音和结果拷走（README 和任务书每周都提醒）。

**联网安装（备用，适合老师或自己的电脑）**：`scripts/windows/install.bat` 建虚拟环境、用清华 pip 镜像安装依赖、下载模型；`start.bat` 启动。

**ffmpeg 查找顺序**：环境变量 `FFMPEG_BINARY` → 系统 PATH → `imageio-ffmpeg` 自带的程序。都找不到时给出中文提示。

**TensorFlow**：便携包不带。第 6、7 组训练用机房自带的 Python（`tools/train_classifier.py` 只依赖 TensorFlow、numpy 和本仓库的轻量文字模块，兼容 TensorFlow 2.10 及以上的 `tf.keras` 常用层）；机房的 TensorFlow 不能用时，老师用 `requirements-tf.txt` 给便携包装扩展。网页工具检测不到 TensorFlow 时自动用关键词规则分类，并在界面上说明。

**Docker**：按 build_spec 10.2 写 `Dockerfile`，只用于以后云端演示；本次不部署。

### 5.10 与 build_spec 不同的地方

1. **各组改进的接入方式**：build_spec 让各组直接改自己那一步的文件；本设计改为"做法登记 + 每组一个文件"，基线保留，配置切换，便于对比和审核（见 ADR 0001）。
2. **参考文本**：build_spec 按剧本导出 24 份；本设计按录音导出 72 份，各自对照录音校对（同一剧本三次录音实际说的话不同）。
3. **分类的文字归一**：build_spec 要求先用步骤 5 的转换函数把汉字数字转阿拉伯数字再替换占位符；本设计改为只用标准库的独立函数（阿拉伯数字串、两个字以上的汉字数字串统一换成 `#`），这样训练脚本能在只装了 TensorFlow 的机房 Python 上运行，且第 4 组改步骤 5 时不会悄悄改变分类器的输入。
4. **分类训练数据**：增加 AI 生成的补充句子，只进训练集。
5. **界面**：增加"数据校对""录音质检"两个标签页和"高级设置"。
6. **部署**：增加 Windows 便携包（GitHub Actions 构建）作为主线，联网安装为备用。
7. **阶段计划**：build_spec 的 P0—P7 保留，另加数据工具、便携包和课程文档（实施计划里细化）。

## 8. 测试决定

- **好测试的标准**：只测对外行为（输入 → 输出），不测内部实现；优先在最高的接缝 `run_pipeline` 上测，再在各槽位的公开函数上测；按 Matt Pocock 的 tdd 做法先写失败的测试再实现，一次一个纵向切片。
- **不需要模型的快速测试**（任何电脑都能跑）：
  - 中间格式 JSON/CSV 往返一致，中文表头和顺序正确；
  - 步骤 1：用 ffmpeg 生成的正弦波、静音（44.1kHz 立体声 mp3、m4a、mp4）转换后为 16kHz 单声道 16 位，原始文件未改，SHA-256 正确，质检能报出"大段无声"；
  - 文件名检查、参考文本导出（72 份）、验收表、冻结版本、Audacity 标签转换；
  - 步骤 5：剧本 `numbers` 的提取正确率（已知失败写成 xfail 并注明原因）；
  - 步骤 6：输出只能是 5 个"疑似·类别"或空字符串；文字归一对汉字读法和阿拉伯数字给出一致结果；
  - 做法登记：每个槽位都有 `baseline` 和各组的初始做法，各组初始做法输出与基线一致；
  - 剧本文本演示：第 8 组剧本跑完步骤 5—8，生成 Word 初稿，声明文字在，标签合法，打印误报率；
  - 分类补充句子检查；
  - 静态检查：代码里没有 `share=True`，`pipeline/` 里没有联网调用，没有写死的密钥；导入 `pipeline` 和 `pipeline.text_norm` 时不会导入 sherpa-onnx。
- **冒烟测试**（模型已下载时运行，否则跳过；测试音频只用于自动测试，不放进演示界面）：SenseVoice 自带 `zh.wav` 和 `0-four-speakers-zh.wav` 走完 VAD 和识别，`use_itn=True` 时有阿拉伯数字；四人测试音频设 4 人时分出 4 人；`run_pipeline` 全流程产出 Word、CSV、JSON、片段 ZIP；网页服务能启动并响应。
- **长录音测试**（单独运行）：把四人测试音频拼成约 60 分钟，记录每步耗时、实时率、最大内存，写进 `docs/progress.md`。
- **CI**：上面的快速测试和冒烟测试在 Windows 和 Linux 上都跑；便携包构建后在 Windows 上运行 `tools/selfcheck.py`。
- **不用语音合成生成任何"人说话"的测试音频。**
