# 深度调研任务指令（第 3 轮发给调研代理的完整指令）

为一门高校《语音识别技术及应用》实训课做完整课程设计调研，最终输出中文报告。课程核心是：以语音识别（ASR）技术为主导，紧扣云南（尤其是昆明）数字文旅的发展与落地应用。

【授课者背景】高校教师，教深度学习、Python、Linux Shell、数据库等课程，有农业AI与工业界ML经验。

【课程约束】
- 总学时 36 学时，8 周，每周上一次课，每次 3–4 节。
- 学生：大专/本科生，学过 Python，没学过深度学习。报告需要给出专科、本科的分层要求（同一门课分层教学：基础任务和进阶/拓展任务）。
- 定位：实训课（实践为主，理论够用即可）。
- 现有教材：《语音识别技术及应用》（项目化教材），大纲如下，可作为技术主线参考，但要结合当前流行技术栈进行更新和取舍：
  基础篇：项目1 搭建语音识别开发环境（语音识别概述、概念、应用领域、发展历程；主流框架：语音前端处理、解码识别；常用语料库；开发工具：工具包、Python库、TensorFlow、NLTK）；项目2 语音特征提取（预处理：预加重、分帧加窗；短时傅里叶变换；语谱图、Fbank、MFCC 提取；项目实施：MFCC 特征提取与可视化）。
  技术篇：项目3 构建传统声学模型（HMM、GMM-HMM，HMMlearn，基于GMM-HMM的孤立词识别）；项目4 使用深度神经网络构建声学模型（DNN原理与编程、DNN-HMM，数字命令语音识别）；项目5 训练语言模型（N-gram、平滑算法、评价指标、RNN语言模型，项目实施：用RNN构建歌词生成器）；项目6 构建语音识别系统（传统系统、端到端系统：CTC、注意力机制；项目实施：基于CTC的端到端语音识别系统）。
  应用篇：项目7 中文普通话语音识别。
  每个项目结构：项目目标、描述、分析、准备、实施、实训、总结、考核、评价。

【需要调研并给出的内容】
1. 当前（2025–2026）主流、适合教学的中文语音技术栈调研与推荐，比较其教学适用性、硬件需求（机房CPU/少量GPU）、安装难度、中文与方言支持：例如 FunASR/Paraformer、SenseVoice、Whisper（及 faster-whisper）、sherpa-onnx、WeNet、k2/icefall、Vosk、torchaudio、librosa、PyTorch（对比教材的 TensorFlow）、VAD（如 silero-vad、FSMN-VAD）、关键词唤醒（KWS）、说话人识别、TTS（如 CosyVoice）、ASR+大模型（LLM）组成的语音对话/RAG导览链路、Gradio/Streamlit 快速原型、国内云API（讯飞、阿里等）作为对照。明确哪些该保留教材里的传统内容（MFCC、HMM原理可做概念教学），哪些该用现代工具替代，理由是什么。
2. 云南数字文旅中语音识别的真实应用与政策背景：云南/昆明智慧旅游、"一部手机游云南"等项目现状、文旅部数字文旅相关政策、景区智能导览、方言与少数民族语言语音资源（云南方言、昆明话、彝语/撒尼、白语、傣语等的语音数据集或保护项目，如中国语言资源保护工程）、非遗口述史数字化、户外噪声环境下的ASR鲁棒性问题。也参考成都大熊猫"花花/和叶"IP与文创、数字人导览、语音交互文旅案例。
3. 基于以下既有构想设计实训项目（要把这些构想变成学生可在课内完成的项目）：
   - 为云南文化符号设计"轻人设讲述者"语音导览（如滇池红嘴鸥"小鸥点点"、昆明瓦猫"瓦小守"、石林阿诗玛、普洱"老茶爷爷"、大理扎染、会泽斑铜等"角色图书馆"），要求系统能听懂游客口语化、非标准提问（如昵称、口语），做意图识别与热词/自定义词表；
   - 游客与本地人"口述记忆共建"闭环：授权采集 → ASR转写 → 打标签 → 人工审核入库 → 再分发；
   - "实体文创+语音交互"：扫码语音对话、录制个人旅行语音绑定文创；
   - 户外噪声容错设计（识别失败给出口语化提示）；
   - 原则：不歪曲少数民族文化、隐私授权合规（个人信息保护法对语音数据采集的要求）。
4. 输出一份完整的 8 周 × 36 学时课程设计：每周主题、学时分配、理论要点（给没学过深度学习的学生讲到什么深度）、实训任务、使用的工具/模型、与教材对应的项目章节、专科与本科的分层要求、课堂产出物。建议最后 2–3 周为综合项目（小组做一个云南文旅语音交互原型）。
5. 考核方案：过程性考核与项目考核比例、评分量规（rubric），含技术指标（如字错率CER的测量）、文化内容准确性、合规性、演示。
6. 教学资源清单：公开中文语音数据集（AISHELL-1、THCHS-30、Common Voice 中文、KeSpeech 方言数据集等）、预训练模型下载源（ModelScope、Hugging Face 及国内镜像）、机房环境配置建议（conda/Docker、离线部署、GPU不足时的方案）。
7. 可能的风险和坑：国内网络访问问题、机房算力不足、学生深度学习基础薄弱、方言数据稀缺、项目流于"调API"而学不到原理等，以及对应对策。

【输出要求】中文报告，结构清晰，结论直接，给出明确推荐而不是中立罗列；有技术选型取舍理由；尽量引用可靠来源（官方文档、GitHub、政策文件、论文）。
